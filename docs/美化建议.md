## 1. 三件"补缺"提案

### 1.1 站点身份件：favicon + theme-color + OG 社交卡 【推荐先做】

> ✅ **2026-09-28 已挑中并落地**，登记在 `docs/设计规范.md` §13a。三条实测结论与本文不同的地方：
> ① favicon 用两版文件 + `<link media>`，不是一版 SVG 内写 `@media`（换系统外观不重绘）；
> ② `theme-color` 只写亮色一档，暗的那次由首帧前的内联脚本改——无 JS 时页面本来就是亮色，写两版反而在骗人；
> ③ OG 卡只能拿 headless Edge 出图，内置浏览器视口 724px 宽、够不到 1200。
> 另踩到一枚新坑：**XML 注释里禁 `--`**，注释写了 `--moss` 会让整张 SVG 静默解析失败而 build 全绿。

- **为什么**：唯一"真的缺"而不是"可以更精"的一项，且落在站外——现在最露毛坯的一面。
- **做什么**：
  - favicon：一枚同族色的极简 SVG（雾形 / 一道林线 / 一滴露，三选一），亮暗自适应或给两版，**不引外来色**。
  - `theme-color`：亮 `#F2F4EF` / 暗 `#0E130D`，让移动端浏览器 chrome 跟主题走。
  - OG 卡（1200×630）：`og:title` / `og:description` / `og:image` + `twitter:card`。
- **OG 图的两条路**：
  - **纯排版卡（默认推荐）**：站名 + 一句 + 雾底渐变，全用现有令牌，不碰照片——零规范冲突，也更贴"身份是排印 + 雾，不是摄影"。
  - 照片卡：裁首屏那两张之一叠纱罩 + 字。**要先在 §5 给"社交预览图"一个名分**，否则撞"照片只许出现在首屏背景与内容位"那条铁律。
- **预算**：小–中。favicon/OG 是新增素材进 `public/`；规范 §13 补一节登记。
- **代价 / 撞哪条**：不碰动效预算、不碰色板纪律。唯一要过的是 OG 图归属，纯排版方案直接绕开。
- **怎么验**：浏览器标签页看图标；用 `og` 调试器或直接把链接丢进支持预览的客户端看卡片；`theme-color` 在移动端 chrome 看顶栏颜色。

## 2. 专题：子页面为什么"淡"，以及怎么不靠堆料救回来

### 2.0 机械成因（实测）

`mistwood.css:67-68`：

```
body{ background:linear-gradient(180deg,var(--bg-top) 0%,var(--bg-base) 40vh);
      background-color:var(--bg-base); }
```

开场 40vh 之后，整页剩下的部分就是**一整片平色**。子页的氛围层只有三样：全局颗粒（α .035）、标题背后那一条静态气带（`.page-head::before`，z-index:-1）、顶部 40vh 跟时段走的 `--bg-top` 色温。

对照首页：照片 + 纱罩 + 三条雾带 + 萤火虫 + 雾灯，五层叠出来。

所以"淡"的本质不是颜色太浅，是**首屏是被一盏灯照亮的，子页是一张没打光的平纸**。从首页点进子页，像从有光的林间空地走进一间没开灯的屋子——落差在这里。

下面四条都围绕同一件事：**给子页也打上光，但用静态的、不抢戏的方式**，全部落在 §1.4（三种模糊）/ §1.2（一处动）/ §2.4（对比度地板）/ §12 的允许区内。

### 2.1 【头条创意】给子页同一盏灯：方向光落地到背景，且随时段转

> ✅ **2026-09-28 已落地**，登记在 `docs/设计规范.md` §2.3 末。⚠️ **本文给它写的那条"唯一硬风险"方向是反的**：
> 原文说"一层光压在 `--bg-base` 上会抬高局部背景亮度，深色文字的对比度会往下掉"——**亮色里底越亮，深色字越清楚**，
> 实测 day 顶 `#EDE9DD` → `#EFEBDF` 时 `--ink-2` 是 4.89 → **4.98**（升）。所以"把光锚在阅读栏之外"
> 从安全条件降级成了审美条件；真正有天花板的是**暗色**（那里的字是浅的，抬底就是吃余量），
> `--ink-2` 在 α .08 时 4.75、**.12 时 4.34 破 4.5** —— 暗色那盏的上限由这一格定死。
> 门禁跟着扩了一档（`palette-check` 第四件事），两次变异测试都红，细节在规范里。

- **为什么**：直接对症"淡 = 没光"。而且首屏的光源方位是**实测钉死的常量**（§5：亮色横向三分亮度 左 .83 / 中 .73 / 右 .58，光从左上来），§2.3 又让这盏灯的**仰角随时段转**（投影四档）。子页现在完全无视这套光——把同一盏灯接到子页背景上，等于让全站共用一个太阳，从首页走到子页是"走进同一束光里"，不是"走进空白"。这是把已签字的机制（§2.3 光的方向）延伸到它还没覆盖的地方，有先例、有理由，不是新 gimmick。
- **怎么做（推断，落地前必须截图验）**：
  - 在子页 `body`（或一层 `z-index:-1` 的底）叠一个**极淡的径向/线性方向光**，锚在**左上**（和首屏同方位），用苔族或暖顶色，α 控制在 .02–.05。
  - **光落在留白里，不落在阅读栏上**：阅读栏居中（≥1240px 时左缘约 280px），左上方向光主要打在左上角的空白与页头区，680px 正文栏基本还坐在近纯 `--bg-base` 上——这既安全（不拖对比度）又正确（§2.3 光就是从左上来）。
  - **随时段转仰角/暖度**，复用 §2.3 的 `data-phase`：清晨光更长更软、正午收得紧、傍晚最暖（可借一点枯草金，但守"每屏 ≤2 处"配额）、夜里最冷最淡。暗色那盏是"压暗周围"的月光逻辑（§2.2），不是提亮，单独配。
- **预算**：中。方向光本身零动画零模糊（渐变不是模糊，§1.4 不增项）；贵的是时段四档 × 亮暗两套的取值 + `palette-check` 六档回验 + 双主题截图。
- **代价 / 撞哪条**：
  - 对比度是**唯一硬风险**：一层光压在 `--bg-base` 上会**抬高**局部背景亮度，深色文字的对比度会**往下掉**。所以必须 (a) 把光锚在阅读栏之外，(b) 用最坏一格文字单元跑 `palette-check`，掉出地板就收 α。这条不验证不上线。
  - 不碰 §1.2（静态，零 infinite）、不碰 §1.4（渐变非模糊）、不碰 §5（渐变非照片）、不碰 §12。
- **怎么验**：双主题 × 四时段截图；`palette-check` 六档；重点看阅读栏里的正文对比度有没有被光拖下来。

### 2.3 子页开场"气"的体积感

> ⛔ **2026-09-28 判定：不做。** 理由不是"没预算"，是**这条的活已经被 §2.1 接走了**——子页现在从
> `--lit` 那一团亮里走出来，开场薄不薄取决于光的半径，不取决于带子的条数。再加第二条带子要付两笔账：
> ① §2.4 登记的那笔（带心把 `--ink-2` 推到 5.26/5.04）得重算，"提亮一次"就"吃一次对比度余量"，
> 而这余量现在正被那盏灯用着；② 本文自己那句"雾加多容易读成'又是同一招'而不是'更深'"是对的，
> 而且比预想更成立——灯已经把这一页打亮了，第二层雾只会把灯踩灭。**留档，不算欠债。**

- **为什么**：现在进场只有一条横向气带，"从雾里走出来"在子页只剩薄薄一拍，和首页的厚度落差大。
- **怎么做**：把单条带子升级成**更有体积的静态进场**——比如两条错相的带子、或一条带子 + 一道极淡的竖向光柱，仍 `z-index:-1`、仍静态、仍只用 `blur(28px)` 这一档（§1.4 的"背景雾化"，复用不新增）。
- **预算**：小。
- **代价 / 撞哪条**：雾加多容易读成"又是同一招"而不是"更深"，且带心提亮会推 §2.4 那几个数（§2.4 已登记带子把 `--ink-2` 推到 5.26/5.04，再加一层要重算）。收益边际小于 2.1，**建议排在 2.1 之后**，甚至可能被 2.1 的方向光覆盖掉一部分职责。
- **怎么验**：双主题截图 + 重跑带子那笔对比度账。

### 2.4 阅读页的"纸"与"墨"层次（低风险的微深度）

> ⛔ **2026-09-28 判定：两条都不动。(b) 是看了真图才定的，不是抽象定的。**
> **(a) 680 栏垫暖纸色——否。** 它和 §2.1 的方向光是同一件事的两种做法（都为了"这一页被照着"），
> 灯已经落了，两层一起上就是重复付款；更硬的理由是**一条有边界的色带会在 680 两侧留下可见的列边界**，
> 那是站里第四种材质——§12 否纸张纹理用的是同一条理由。
> **(b) H2 加排印重量——否。** 拿最长那篇在真浏览器里滚到第三章截图看：30px 的宋体压在 18px 正文上
> 是 **1.67 倍**，上面还挂着那枚 32px 苔绿短线，"章"已经站住了。更硬的一条是**这套站里层级从来不由字重拉开**：
> H1 42 / H2 30 / H3 22 全是 600（`essay.css`、`mistwood.css` 实测），差的是尺寸和那根短线——
> 单独把 H2 拧到 700 不是"更有分量"，是把一条一致的表达方式换成另一种。
> 短线与上文 64px、与标题 16px 是现值，读起来是"章有呼吸"，不是"淡"。
> ⚠️ 这一格顺带记一条**截图方法上的坑**：无头 Edge 带 `#sec-1` 这种片段进页面时，整页会拍成空白——
> `.reveal` 的入场是 0.8s **transition**，虚拟时间预算在过渡起跑前一帧就截了图。真浏览器里同一地址
> 3/4 个 `.reveal` 已 `in`、刻度第二枚点亮、TOC 同步。**别把这张空白当成深链坏了。**

### 6.1 关于页桌面双栏——最直接的"去空" 【实测】

> 三处与本文不同，都是落地时改的：① 人像那一列按**实际显示宽 220px** 排（本文写的 ~276px 是那张图的原始尺寸），
> 栏间距 60px；② 容器为这一行放宽到 **880px**，但**阅读度量不跟着放**——其余各块 `max-width` 收回 680、
> 左缘对齐人像，所以 §4 那条"正文阅读区收窄 680"对整页仍然成立；③ 窄屏那层包装**什么都不改**
> （`.about-lede` 在媒体查询外是 flex 竖排、gap 与父级同值），回退不产生第二种形状。
> ⚠️ 本文留的那个悬念（紫会不会更扎眼）答案是**不会**：双栏之后人像不再独自坐在 680 窄带的正中，
> 旁边是简介而不是大片空底，那枚紫没有变得更显眼。§13 那档 `saturate(.35)` 继续待命
> （它的代价是脸会灰掉，本来就要等作者点头），这条不为它让位。

- **现状**：`.about-inner` 是 `max-width:680px` 的居中单列竖堆（人像 → 简介 → now → 联系方式 → 档案）。1440 桌面下整页是一条窄带、两侧大片空——**关于页的"空/淡"主要来自版式，不是颜色**。276px 的人像独自坐在 680px 列里，下面才是文字，读起来像把手机布局拉伸到桌面。
- **建议**：把*简介段*（只有两句，不是长阅读）与人像在桌面排成左右两栏——人像左 ~276px、简介右——读起来像手记扉页的构图。now / 联系方式 / colophon 仍在下方。

- **预算**：小（一段 ≥1024/1240 的 grid + 窄屏回退单列）。
- **撞哪条 / 怎么验**：不引新材质。双主题截图；留意人像那处紫（§13，家族外）在更宽的构图里会不会更显眼——若更扎眼，这条要让位给 §13 那枚 `saturate(.35)` 旋钮的决策。

## 7. 动画建议

先说大实话：**常驻氛围的动效预算已经签满，而且它就是"高级淡雅"的护城河**——子页只许颗粒 + 至多一个呼吸点，这是规格不是欠债。所以"丰富"**不该往环境动画里加**（那会背叛淡雅，§12 也否了一整批）。真正还有安全余量的是两类：

### 7.1 滚动驱动的微动——页面回应"你在读"，而不是自己在那动

> **2026-09-28 三条各归各位：① 落了，② 随 §6.2 一起等，③ 否。**
> ① 刻度随滚动点亮当前章——已和 §6.3 一起做掉，走的就是"属性更新不是动画"那条口径（每个滚动帧
> 一次 class 切换，无 `animation`、无 infinite，不占常驻预算）。⚠️ 它比预想的难：点亮用的必须是
> **没被夹过的** `-r.top`，用进度线那把夹过的尺子时最后一章永远不亮。
> ② 年脊柱高亮当前年——挂在 §6.2 上，同一触发条件。
> ③ 方向光随滚动移仰角——**否**。这条正是本文自己警告的那类"量不出读得出"：那盏灯的可见性取决于
> 光心落在留白还是纸上，而 `--lit-at` 是相对 100vh 的百分比，几个百分点换算下来是**几十像素**，
> 要在一枚半径 `56vmax`（1440 宽下约 806px）的渐变边沿上被读出来——结论是它不构成一次"回应"，
> 只会把那盏灯从"环境"变成"跟手的东西"，而跟手是 §12 否过的另一族。
> **减一层皮不换一次心跳。**

- **模型**就是已有的 §8.7"身后的雾"：scroll 更新属性、无 `animation`、无 infinite，**不占常驻预算**。
- **可做的**：① §6.3 进度线刻度随滚动点亮当前章节；② 列表页滚动时年脊柱高亮当前年；③ 子页方向光（§2.1）随滚动极轻地移一点仰角——像走着走着太阳偏了。
- **第③条最险**：量不出"读得出"就别上——§12 否过"看不见的内部微动"那类（雾带加速 15% 那条），要确保是*读得出*的回应，不是自我感动。
- **撞哪条**：全部走"属性更新不是动画"的口径（§6 苔时弧同族）；reduced-motion 下要单独问"它退成什么"。

### 7.2 交互反馈补全——给还没反馈的可点件一个主反馈

> ✅ **2026-09-28 审过，结论是"没有可补的"——这条以负结果收。** 做法不是肉眼翻 CSS，是把页面上
> 每个 `a[href] / button / summary` 拿 `document.styleSheets` 里**所有带 `:hover` 的选择器**逐条
> `matches()` 一遍（选择器先剥掉 `:hover` 再匹配元素）。结果 **0 缺项**。
> ⚠️ 第一版手写清单报了 16 处"没反馈"，全是假的——导航链接、设置面板的 radio、`<summary>` 各自被
> 更上层的规则覆盖着。**"看着没写"和"匹配不到"是两件事，只有后者算缺。**
> 这一轮唯一真补上的反馈在 §1.2 那格：`.thing` 以前**一律**是 `<a href="#">`，点了跳页顶，
> 现在没填真地址就**不给 `href`**（实测四张卡：`hasAttribute('href')` 全 false、`cursor` 回到 `auto`），
> hover 反馈也一并收进 `.thing[href]`——**反馈跟着可点性走，不给假链接配真反馈**。

- §8.3 规定每个可点元素 1 个主反馈。与其加新动画，不如把子页里"悬停/点了没反应"的可点件补齐——这比任何新动效都更对症"高级"（高级感很大一块是"每个该回应的地方都回应了"）。
- **撞哪条**：悬停 ≤3 属性、走 §8.8 白名单。

### 7.3 跨页转场先不动

> ⏸️ **2026-09-28 复核：仍不动，理由照旧。** 这一轮往转场里塞东西的机会出现过两次（§2.1 的灯、
> §2.2 的年轮），两次都选了"落在页内"而不是"落在 80ms 里"——转场那 80ms 是全站唯一一处
> **不属于任何一页**的时间，往里加东西没有承接它的设计系统，只有承接它的错觉。

80ms 翻书停顿已签字，往里面再塞雾/光风险高、收益读不出，列在"先放一放"。

## 8. 让博客"活"起来：丰富的正确来源

**对博客，"丰富"的正确来源是内容本身的呈现——时间、声音、阅读结构——而不是更多的雾和光。** 子页淡，根子是*内容被平铺呈现*（一张平表、一根平栏），不是缺装饰。三条显形：

- **让时间在场**：年轮（§2.2）/ 年脊柱（§6.2）/ 进度刻度（§6.3）/ 详情页已有的 post-when。博客是一条时间线，把这条线显形，页面就有"编年"的厚度，而不是 brochure 的平。
- **让声音在场**（⚠️ 第七轮就地指认：这里的"声音"＝**作者的语气**，不是 `docs/设计规范.md` §18 那个**听层**——那一路听觉输出第七轮被判成"未开工"，名字与账都在 §18.0）：首页收尾给 note 分量（§6.4）。可选更进一步——详情页文末挂一条"写这篇那阵子记过的 note"，把 essays 和 notes 两本手记缝起来；**这需要作者写，机制可先留位**，不写就不出现（§12 不造假）。
- **让结构在场**：进度刻度 / TOC / 边注。长文给读者骨架，读起来被照顾＝高级。

**光**（§2.1）负责治"氛围的淡"，上面三条负责治"内容的淡"。两者一起，子页才从"没开灯的平纸"变成"被光照着的一页手记"。

> **2026-09-28 三条的落点**：时间在场 ✅（§2.2 年轮 + §6.3 章节刻度 + 详情页本就有的 post-when）、
> 声音在场 ✅（§6.4 首页收尾）、结构在场 ✅（刻度 / TOC / 边注）。
> ⛔ 唯一没做的是"文末挂一条写这篇那阵子的 note"那句里的**机制留位**：现在挂，落点就是一段
> 永远为空的容器——`notes` 只有 3 条，与 3 篇 essay 的日期两两错开，缝不上。
> §12 说的"不造假"包括不预留一个只会显示空缺的位置。**等真有一条要挂的 note，机制跟着内容一起来。**

**明确不靠这些来"丰富"**：加环境动画循环、加照片/粒子/纹理、提饱和引外来色——都是 §12 否过的，且都会毁掉淡雅。
