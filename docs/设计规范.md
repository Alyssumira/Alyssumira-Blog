## 0. 一句话定义

晨雾森林 = **磨砂，不抛光**。一切材质是哑光的，一切动效是慢的，一切颜色来自同一家族（雾、苔、墨、枯草）。

## 1. 高级感五律（最高优先级）

1. **同族色，不靠撞色**——层次靠明度和透明度差，不靠色相跳。全站无外来色。
2. **一处动，处处静**——任一时刻屏幕上只有一处明显在动。
3. **慢比快高级**——常驻动效周期 ≥ 15s（雾带 65–95s、萤火虫 16–24s、"现在在做"呼吸点 16s）；交互反馈 0.3–0.6s；没有 1s 以内的"活泼"动画。唯一例外是颗粒，⚠️ 但这一条例外**这轮被查出实现值比登记值快四倍**：`animation-timing-function` 是**逐关键帧区间**生效的，`grain-shift` 有四个区间（0/25/50/75/100%），写 `steps(4)` 得到的是 4×4＝16 个位置／1.2s＝**每 75ms 换一次全场点阵（13.3 Hz）**，不是登记的那句"1.2s 跳四帧 ≈ 3.3 Hz"。实测口径：`getAnimations()[0]` 暂停后把 `currentTime` 钉在 0/75/150/225/300ms，四档各有不同的 `transform`；改成 `steps(1)` 之后同一组采样是 `0 / 0 / 0 / 0 / -21px`——一周期真四跳，300ms 一跳，回到签过字的那个数。⚠️ 顺带一条规范级的教训（下次判"某个循环要不要留"要用）：**一枚循环的可见响度不只看它自己的周期，还看它是不是这一屏唯一在动的东西**。颗粒在首屏是和雾带竞争的"材质"，在子页面上它就是全场——同一枚 13 Hz 在前者几乎不被注意、在后者读成"整片在沸腾"。帧率这件事也有个中间地带：≥24fps 糊成材质、≈3Hz 读成"偶尔换一张"，只有 10–15Hz 两头都不像，最难看。
4. **全站只许三种模糊**——背景雾化（雾带 `blur(28px)`，极大极淡，顶掉旧方案里的"光斑"）、玻璃材质（导航 `blur(18px)`／图鉴玻璃条 `blur(14px)`）、入场虚焦（内容照片 `blur(10px)`，0.6s 散开，桌面限定）。其余全实。
5. **数值必须"故意"**——字距、行高、圆角、透明度不许出现默认值气质。

**动效预算（硬约束）：**

| 类型 | 上限 | 备注 |
|---|---|---|
| 常驻循环 | 首屏 ≤ 3（雾带 ×3，或雾带 + 萤火虫），子页面只剩颗粒 | 雾带是"空气"，不算装饰。⚠️ 实测 `getAnimations()` 发现 `/about/` 跑着 2 条 infinite（颗粒 + "现在在做"呼吸点），而 §1.3 又把呼吸点列为合法常驻——两处说法此前打架，现登记为**唯一例外**：子页面 = 颗粒 + 至多一个呼吸点（5px、16s linear）。⚠️ 子页开场那条气带（§15）**是静态渐变、零 infinite**，所以这条预算一个字没改。⚠️ 另：显示设置里"颗粒 = 无"可以把这条唯一必留的循环也停掉——地板由用户自己踩，不是规范松了（§15）。⚠️ **第五轮两条**：① 详情页读到文末时颗粒**自己退场**（`data-quiet`，§8.7）——所以"子页面 = 颗粒 + 至多一个呼吸点"在文末那一格是 0 条，**预算是上限不是义务**，为了让循环"始终在跑"而取消退场才是违反这一行；② 那条滚动驱动的**身后的雾不占本行名额**——它没有 `animation`、不 infinite，是随滚动更新的 `mask-image`（和 §6 苔时弧那一档"属性更新不是动画"同族） |
| 入场动效 | 每区块 1 组，区块间不复读 | 组内可错落 |
| 交互反馈 | 每个可点元素 1 个主反馈，悬停变化 ≤ 3 个属性 | 位移/透明度/缩放。能动的属性见 §8.8 白名单 |
| `prefers-reduced-motion` | ⚠️ 必须 `animation:none` 并直接落到终态 | 无例外。只把 `animation-duration` 改短**不算降级**——保留 `infinite` 会把它变成 10ms 一次的频闪，比不降级更糟；`scroll-behavior` 也要一起关。⚠️ 但**颜色与不透明度过渡保留 200ms**（§8.8）：一并砍掉会让主题切换变成亮度突跳，那正是 §12 禁的事。⚠️ **第五轮补一条口径**：`animation:none` 管不到**滚动驱动**的效果——详情页身后那条雾（`mask-image`，§8.7）没有 `animation`，要撤必须在媒体查询里点名 `mask-image:none`，否则"降级了"只是我们的错觉。**凡是"随输入更新的样式"都要单独问一句它在减弱偏好下退成什么**（同族的还有 §6 苔时弧，那条是属性更新、本来就是静止的，不撤） |

### 2.3 时段色温（变化幅度必须小于"能说清"的阈值）

| 时段 | 天气词 | 亮色模式变化 |
|---|---|---|

| 09–傍晚 day | `light` | 基准态，雾散开；⚠️ 投影＝§2.1 那枚基准值（一天里仰角最高、影子最短） |
| ⚠️ 傍晚 dusk（窗口随季节，见下表） | `dusk` | 暖顶带枯草金 `#EDE4D2`；⚠️ **枯草金当主角的落地方式** = Hero 斜体词换成 `--straw`，本屏 2 处配额里只用 1 处；⚠️ 投影全年最长 `0 26px 38px -14px` α.14 |
| ⚠️ 傍晚结束–05 night | `night` | 仅微青压暗（`--bg-base:#EDF0EA` / `--bg-top:#E4E7DE`）；⚠️ 投影收到几乎无影 `0 6px 16px -10px` α.10；萤火虫 3 颗（暗色 6 颗）；首屏那一格"此刻的话"在这段里说的是"守夜"（§6） |

⚠️ **换季：日循环之上再套一层年循环**（2026-09-27 第四轮）。原先四个时段只按小时切，等于默认"全年日落同一时刻"。现在**只有傍晚的两端在动**，`dawn` 05–09 与 `day` 起点 09 不动，`night` 从傍晚结束处接手——四个时段因此永不重叠，也不需要第二张表：

| 季 | 月 | 傍晚窗口 |
|---|---|---|
| 冬 | 12·1·2 | 16:00–17:30 |
| 春 | 3·4·5 | 17:30–19:00 |
| 夏 | 6·7·8 | 19:30–20:30 |
| 秋 | 9·10·11 | 17:00–19:00 |

三条账要交代：**① 幅度**——季节之间最大差 3.5 小时，摊到每天不到 2 分钟，比日变化低一个数量级，所以本节标题那句"变化幅度必须小于能说清的阈值"照样成立（访客读到的是"今天傍晚特别金"，不是"网站换了时刻表"）。**② 例外会跟着浮动**——§12 那条"每屏至多 2 处枯草金（傍晚时段除外）"里的"傍晚"从此是一个区间而不是常量，配额审计要按当季窗口看。**③ 代价**——`data-phase` 的判定从"取小时"变成"取小时＋分钟＋月份"（`site.js` 里 `SEASON_DUSK` 那张四行表），而**暗色的投影仍旧完全不随时段变色**（下面那段没变）。⚠️ 2026-09-28 起这句要说准：暗色不转**影子**，但开始转**色温**了——见本节末那条暗色三段色温。

⚠️ **光的方向（第五轮）**：同一条 `data-phase` 现在也转**投影**——正午是基准那枚 `0 12px 24px -8px`，清晨抬成低角度长影，傍晚走到全年最长，夜里收到几乎无影（四档值见上表）。访客读出来的是"卡片离桌面的距离在变"，不是"网站换了阴影参数"，量级和上面那条"幅度账"同级。三条硬约束，都是这轮自己定的：

- **只转仰角和长度，不转方位。** 方位被那张照片钉死了：§5 实测亮部在左（暗色标题区横向三分 左 .076 / 中 .069 / 右 .059，亮色 .83 / .73 / .58）。内容区的影子一旦往右倒，就等于和首屏分属两个太阳，**比"光不动"更错**。所以全站光源方位常量＝左上，变的只是高度。
- **4 处 `text-shadow` 一律不参与。** 它们全是 `0 1px`——那是"字抬起来"不是光照方向（§5 铁律 3 的光晕层），跟着转会变成歪影。
- **不给 `box-shadow` 加 `transition`。** 换档那一刻离散改值，一秒一跳。理由在 §8.8：`box-shadow` 不在白名单里，淡一个 24px 的投影＝每帧重绘一次阴影；而时段切换本来就发生在"没人正盯着卡片"的时刻，突跳读起来是"云过去了"，慢淡反而读起来是"控件"。
- ⚠️ **能拧的那一枚**：这条跟着 `data-phase` 走，而 `data-phase` 只在亮色里生效——**切到暗色就是整条关掉**（夜林是"另一个时刻"，它没有太阳，见下面那段）。所以本轮没有为影子单开旋钮：抽屉里那四枚只管"往回收"，而"换个时刻"这件事本来就有主题切换在管。要调档只改 `mistwood.css` / `home.css` 里那三行 `--shadow`，两份取值必须逐字符相同（`palette-check.mjs` 现在会比对，见 §16）。

⚠️ **同一盏灯现在也照在子页上**（2026-09-28，`docs/美化建议.md` §2.1）。首屏是被照亮的，子页原先是**一张没打光的平纸**——body 那条 40vh 渐变落地之后就只剩一整片平色。现在 `.wrap::before` 叠一层左上锚定的径向光，`--lit` / `--lit-at` / `--lit-r` 三枚令牌随 `data-phase` 转**仰角与暖度**：清晨低而长、正午收得紧、傍晚全年最长最暖、夜里最冷最淡。

- **方位是常量，只有仰角在动**——和上面那条投影同一条铁律（§5 实测照片亮部在左）。夜林没有太阳，所以暗色那盏是**月亮**：色取 `--moon`、α .05、**不随时间转**，"暗色不参与日循环"一个字没改；它的方位仍然是左，因为夜林那张照片的亮部也在左。
- ⚠️ **挂在 `.wrap::before` 而不是 `body`**，三条理由：① `.wrap` 只有五个子页有（首页是 `.hero`），选择器自己就把首页排除在外——首页已经有照片和纱罩，再叠一盏等于两束光；② `home.css` 里另有一份 `body{}`，写 body 的话"谁赢"要看打包顺序（§8.8 那句"那是运气不是设计"）；③ `z-index:-1` 让它在文字之下绘制，和 §15 那条"气必须在 -1"同一个理由。
- ⚠️ **它是"底"不是"纱"**：不是蒙在内容上的一层半透明，而是地面自己的照度。两件事跟着变：① `prefers-reduced-transparency: reduce` **不撤它**（那条管的是"隔着一层看"的玻璃与雾，地面不在其内）；② **`docs/美化建议.md` §2.1 写的那条"硬风险"方向是反的**——原文说"光压在 `--bg-base` 上会抬高局部背景亮度，深色文字的对比度会往下掉"，实测**亮色里提亮底是把对比度抬上去**（day 顶 `#EDE9DD` → `#EFEBDF`，`--ink-2` 4.89 → **4.98**）。深色字配浅色底，底越亮越清楚，这条没有下行风险。**真正有天花板的是暗色**：那里的字是浅的，往上抬底就是吃掉余量——`--ink-2` 在 α .05 时 5.09、α .08 时 4.75、**α .12 掉到 4.34 破 4.5 地板**，所以暗色那盏的上限由这一格定死，不是由审美定。
- **门禁认这一层**（§16 第四件事）：`palette-check.mjs` 不量半径、不量方位，直接按**最坏假设**判——把 `--lit` 合成进有效底顶、当作铺满全页，再复算一遍地板。跑 12 档，最紧的一格是 `light dusk` 的 `--ink-2` **4.76**（地板 4.5）。**几何只决定你在哪儿看得见它，安全由这条兜住：哪怕它铺满全页，正文与次要档仍在地板上。** ⚠️ 判据自带防空转：`--lit` 缺失或 α=0 直接红（§16 那条"rgba 漂移检查静默空转、长得像全绿"是前车之鉴）。两次变异测试都过：暗色 α 提到 .55 → exit 1（`--moss-ink` 掉到 2.30）；删掉 `:root` 的 `--lit` → exit 1 并打印"方向光的判据正在空转"。
- 零 animation、零 filter、零新模糊（§1.4 三种模糊一个都没多）、不占 §1 常驻预算——和 §15 那条静态气带同一口径。

⚠️ **节气不做成算出来的**。导航那一格 `06:12 · mistwood · fog` 是全页唯一承诺"分钟级真实"的地方（§6 时钟零动效、15s 校准），而 24 节气的间隔在 14–16 天之间且按**时刻**定——本地数组要么写死当年（明年就是死数据），要么用近似式。**近似不配站在分钟级时钟旁边**。解法是把这一格挪到它本来就在的地方：关于页 `last walk · 2026.09.25 · weather: light rain` 那一行**已经有作者手填的 weather**，`src/data/site.js` 的 notes 条目因此多了一个**可选第四键 `jieqi`**——填了就在 `last walk` 末尾显示，空着什么都不画（当前三条 notes 都没填，所以今天页面上看不到它；这一格是留给写的人的，不是我替他填）。

✅ **暗色三段色温已落地**（2026-09-28，路线图 #11 就此关掉）。⚠️ **这一条推翻了本节表里原先那句"暗色不随时段变色（表里暗色列是空的，实现照此保持）"**——那不是观察结论而是一条待办式的禁令，本轮按"继续执行全部计划"（§1.3 在列）改的，暗色列现在填在下面的条件块里。夜林不再只是"一个时刻"，它自己有夜里的时间轴：**傍晚留一点枯草金的余温、凌晨天将亮时极淡青、21 点到 4 点仍旧是签过字那版最冷最静**（基准态，不出块）。四条口径：

- **不新造第二根时间轴**：三段直接骑在现成的 `data-phase` 上——`dusk`＝余温、`dawn`＝极淡青、`night` 与 `day`＝基准。⚠️ 所以边界是 **05 点而不是提案写的 04 点**（`dawn` 从 05 起），为了那一小时再造一根轴、再养一张表不值。
- **只转色相、不转亮度**（这是它合规的全部依据）：两枚底各自锁在自己的 OKLCH **L** 上（`--bg-base` .179 / `--bg-top` .196）只挪 H，WCAG 相对亮度实测差 **≤0.14/1000**。基准 → 余温 → 淡青：`--bg-base` `#0E130D` → `#121208` → `#0A140E`，`--bg-top` `#12170F` → `#16160C` → `#0E1812`。
- **两个方向都停在站里已有的色相上，没有第三个 hue 进站**：暖端朝枯草金（82.4°）走但停在 **H 108**，冷端正好落在月光那个色相上（160.5°，实测 157.6）。§1.1 的同族色底线一个字没碰。
- **回验**：`palette-check` 把这两档当条件块跑（§16），四枚墨全过且几乎不动——`--ink` 14.58…15.13、`--ink-2` 5.57…5.78、`--moss-ink` 9.58…9.94、`--ink-3` 4.09…4.25（与登记的 4.24 同档）。⚠️ **只写在 `mistwood.css` 一处，没抄进 `home.css`**：选择器 `html[data-phase=…][data-theme="dark"]` 权重 (0,2,1) 本来就高过 `home.css` 那份 `html[data-theme="dark"]` 的 (0,1,1)，首页照单全收；抄一份只多出一处要同步的分叉面（§16 那条漂移比对只比"两份都声明的"）。
- ⚠️ **那串 `rgba(14,19,13,…)` 不跟着转**（`--scrim-*` / `--halo` / `--shadow`）：量过，与新底最多差 **5/255**，在近黑上读不出来。而且**亮色的 `night` 早就这么干了**——`--bg-base` 换成 `#EDF0EA` 时 `--scrim-bottom` 仍旧是 `#F2F4EF`，差 5 个单位，从第三轮起到今天没人看得见。所以这不是 §1.3 新引入的口子，是既有口径；真要收口，办法是把这些 rgba 改成 `color-mix(in srgb, var(--bg-base) N%, transparent)`，那是 §16 那条重复债的活，不挂在这条上。

天气词初值必须和 `data-phase` 初值同档——静态 HTML 里写 `data-phase="day"` 就把词填 `light`，别留 `fog`。

### 2.4 对比度纪律

正文 ≥ 7:1；次要文字 ≥ 4.5:1；装饰元素允许淡到快消失——**淡是氛围，正文淡是事故**。

⚠️ 这轮补两条口径，否则 §2.1 和 §2.4 会互相打脸：

1. **尺寸档**：≥24px、或 ≥22px/600 的标题级按 3:1 算（`--moss-deep` 只活在这一档）。
2. **装饰档**：`--ink-3` 归此档——它在白底上的上限就是 2.55:1，"把 `--ink-3` 当正文用"必然违规，别指望调它。首屏的观察日志原本是 `--ink-3`，已提到 `--ink-2`（数字部分再提到 `--ink`，保住 §10.4 的层级）。

⚠️ **这轮把上面两条从"逐个实测"改成"按 L 反解"**（`tools/palette-check.mjs`，已接进 `npm run check`）。道理是：OKLCH 的 L 与 WCAG 相对亮度单调对应，所以**对比度档位其实就是 L 的档位**——新颜色该多深，不用先挑 hex 再量，直接反解。以彩度 .02、色相 152°（我们的主色族）为基准：

| 压在谁身上 | ≥7:1（正文） | ≥4.5:1（次要） | ≥3:1（大字/标题） |
|---|---|---|---|
| 亮底 `--bg-base #F2F4EF` | L ≤ .439 | L ≤ .541 | L ≤ .642 |
| 亮顶 `--bg-top #EDE9DD` | L ≤ .417 | L ≤ .520 | L ≤ .619 |
| 暗底 `--bg-base #0E130D` | L ≥ .697 | L ≥ .585 | L ≥ .489 |
| 暗顶 `--bg-top #12170F` | L ≥ .704 | L ≥ .592 | L ≥ .496 |

拿现值回验，**这张表和下面那批实测数字完全自洽**：`--ink` L=.279→13.13 ✓、`--moss-ink` L=.397→8.27 ✓、`--ink-2` L=.500→5.36 ✓、`--moss-deep` L=.559→4.12（预测就在 4.5 线外，所以规范只许它上大字）✓、暗色 `--ink-3` L=.569→4.24（差 .016 不到线，正是"已按实测修正"那条）✓。⚠️ 最紧的两格现在是 `.020` 并列：`--moss-ink` L=.397 对亮顶天花板 .417、`--ink-2` L=.500 对 .520——两个令牌这一轮都是**为了过线才被压深**的（旧值 L=.412 / .514 各只剩 .005 / .006）。⚠️ 但真正的地板不在基准顶，在**傍晚那一格**：`--ink` 11.52、`--moss-ink` 7.25、`--ink-2` 4.70，这三格由下面的条件块检查管着。改这几枚令牌前先跑 `node tools/palette-check.mjs`。

- 用法：`node tools/palette-check.mjs` 查现值（跌破登记档位就 exit 1）；`node tools/palette-check.mjs --need 7` 反解新色该放哪，并直接给一个过线的候选 hex。
- ⚠️ **学的是阶梯，不是"单色相"**。参考站 Firefly 整站压成 `oklch(L C var(--hue))` 一个色相，我们不行：色板色相散布 **78°**（枯草金 82.4°、暖顶 91.6°、苔族 148–153°、月光 160.5°），收成一个 hue 会同时杀掉 §2.3 的时段色温和枯草金配额。§1.1 要的是"不撞色"，不是"只有一个色相"——所以工具**只报散布、不判分**。
- 反解的前提是彩度低（.02 一档）。彩度一高，色域边界会先于对比度把颜色挤出 sRGB，那时 L 与对比度的对应关系会漂——`--moss` 系（C≈.05）与 `--straw`（C=.071）就是为什么表里的实测值要留一手回验。

⚠️ **第五轮：一旦引入时间轴，本节所有"点值"就都变成了区间**——所以门禁先走一步，`palette-check.mjs` 现在除了两个基础块还会**逐档合并 `html[data-phase=…]` / `[data-moon=…]` 的覆盖后复算**（dawn / dusk / night × 满月，共六档），并且**同时读两份表**、把两份都声明过的令牌逐字符比差异。它当场查出两笔从 §2.3 写下那天就存在的违规：

| 令牌 | 旧值 | 违规处 | 新值 | 复算最差格 |
|---|---|---|---|---|
| `--moss-ink` | `#3C513F` | 傍晚顶 **6.81**、夜顶 6.88、清晨顶 6.99（正文档要 ≥7，连基准顶也只有 7.09） | `#384D3B` | 7.25 ✓ |
| `--ink-2` | `#5E6B61` | 傍晚顶 **4.43**、夜顶 4.47、清晨顶 4.55（次要档 ≥4.5） | `#5A675E` | 4.70 ✓ |

两笔的根因是同一句话：**这两个色是被"压在 `--bg-top` 上"当基准量过的，而傍晚/夜里那块顶本来就更深**，所以时段块一提顶，余量就没了。三条要留在这里的：

- ⚠️ **rgba 那一条检查最初是静默空转的**（实测踩到）：漂移比对原本用 `--x:\s*(rgba?\(` 抠值，而 `--shadow:0 12px 24px -8px rgba(…)` 这种"一长串偏移打头"的写法一个字都不中 ⇒ 十六进制那 22 枚过了闸，16 枚 `rgba()`（面 / 影 / 纱）**一格都没比**。改成"值里含 `rgba(`"之后，只动 `home.css` 的傍晚 `--shadow` 一位小数，工具立刻 exit 1；还原后回 0。**任何"扫了但一个字都没匹配到"的检查，都长得像全绿**——新加判据必须做一次变异测试（故意改坏一处，看它红不红）。
- **满月不进这张账**：那一档只动 `--shadow`、雾灯的光晕/半径和两枚装饰点，**不动照片底也不动纱罩**，所以 §2.4 首屏那笔像素账一个字不用重算（工具仍会把它当一档跑，因为它改的是 `--shadow` 之外的令牌时会连色板一起覆盖）。
- ⚠️ **暗色标题在窄屏的余量仍比登记值薄**（就是"照片透字"那组实测末尾单独挂着"与照片透字无关、单独待办"的那一条），桌面宽度（1440×900）的逐像素复测**还没做**，本轮也没做。⚠️ **但挡住它的那个理由本轮已经没了**：原先写的是"内置浏览器 resize 不生效，得换默认浏览器量"，而 §16 现在有一条 headless Edge 按精确尺寸出图的路（本轮 §6.1 的 1440×900 双主题就是这么拍的）。**没做的原因是另一条**：那三个数（最差 3.74 / p1 4.07 / 中位 6.46）用的是 531px 那一套逐像素口径，**换个窗口尺寸重跑必须先复述口径，否则新数和它们不可比**——§16 那条"46/86 与 55/98 三个数不可互比"犯过一次，这条不犯第二次。留给单独一轮。这一条从第四轮挂到现在。

**这条是明知故犯，不是漏网**，四条依据：① 它只作用在**已经读过、正在离场**的那一段，雾线以下一个字都不蒙——那里才是"正在读"；② 亮色正文 5.05 与站名/日志行同档（4.24 / 4.34，氛围档），暗色全程 ≥13.25 完全不受影响；③ 用户能拧——"雾＝淡"时屏顶 8.01，够回正文档 ≥7，`prefers-reduced-motion` 下 mask 整个撤掉；④ 往回滚文字自己走回清晰。**⚠️ 浓档那一行是 `min()` 夹出来的**：不夹的话地板会到 `.487`、屏顶掉到 4.2 以下，等于让一个氛围旋钮作废 §2.4 的地板——与"纱罩不吃 `--fog`"是同一条纪律。**⚠️ 坡道起点如果钉在元素顶而不是雾线上游 100vh，屏顶正文会一路掉到 2.34:1**，那才是事故；这一格本轮就是这么改的。

⚠️ **子页开场那条雾带会推动上面几个数，两个方向都是"底被提亮"**（2026-09-27 算，带心 α = `--mist` 的 .5 × 带子 opacity .75 = .375；夜林是 .07 × .75 = .053）：亮色 `--ink` 11.98 → **12.89**、`--ink-2` 4.89 → **5.26**（压在 `--bg-top` 上）；暗色那层淡苔绿同样把底往上提，所以差值缩小——`--ink` 14.62 → **13.21**、`--ink-2` 5.58 → **5.04**、`--ink-3` 4.10 → **3.71**。**坐在带子里的最小值是 5.26 / 5.04，4.5 那一档守住了**；`--ink-3` 掉的那一点属装饰档，本来就没有地板。带子之外的数字不变。

⚠️ **照片透字（MaskedHeading）实测否决，不实现**（2026-09-27）。设想是把 Hero 标题的字形填充换成首屏那两张照片（`background-clip:text`）。量法不是"平均色比平均色"，是**逐像素**：字形盖住的那个像素 vs 它正背后那个像素。同一冻结帧拍三张（标题隐去 / 实心 `--ink` / 纯照片填充），前两帧相减得到字形掩膜，只取覆盖率 ≥98.5% 的像素（抗锯齿边与 `--halo` 光晕都不参与，所以本表比上面那张表**更保守**），第三帧给出照片在字形里的真实落点。guard = 压在照片上的半透明 `--ink` 层，**α=1 就是今天的实心标题，是本组基准线**。视口 531×559（内置浏览器改不了窗口尺寸，见下方口径说明）。

| 主题 × 拿哪张照片当填充 | α=0 中位 | α=0 时 ≥7:1 的字形像素 | 判读 |
|---|---|---|---|
| 亮色 × 晨雾亮照（同主题那张） | 1.41 | 1.7% | 亮字底叠亮雾，直接糊掉 |
| 亮色 × 夜色暗照（交叉） | 4.26 | 28.5% | 四配里最好的一格，仍不及基准线 |
| 暗色 × 夜色暗照（同主题那张） | 1.57 | 0% | 极性对不上：暗色标题要亮，暗色照片本身是暗的 |
| 暗色 × 晨雾亮照（交叉） | 3.16 | 0.6% | 同上，换个方向也救不回来 |

- **要追平基准线，亮色得把 guard 压到 α ≥ .95**——照片只剩 5% 的贡献，"词里透出森林"这个效果本身已经不存在了；α=.7 时纹理很清楚但中位掉到 5.84（基准线 12.03）。**暗色无解**：α=1 也只有 35% 的像素过 7:1，照片再亮也追不上。
- 连**尺寸档 3:1** 都守不住：α=0 四配的 ≥3:1 像素占比是 23.3% / 73.2% / 6% / 53.6%。也就是说"反正 68px 大字按 3:1 算"这条路同样走不通。
- ⚠️ 附带查出来的一条，**与照片透字无关、单独待办**：同一套像素法在 531px 窄屏测今天的**实心**暗色标题，最差 3.74 / p1 4.07 / 中位 6.46，只有 35% 的像素 ≥7:1——而登记值是 10.04。两个口径差在：登记值含光晕（§5 铁律 3 的 35% 覆盖估算）且是桌面视口；本表不含光晕、且窄屏的 `cover` 裁切会把亮雾带搬到标题背后。**不能据此说登记值错了，但暗色窄屏的余量明显比登记值薄**，要在桌面宽度复核一次（内置浏览器 resize 不生效，得在默认浏览器里量）。

⚠️ 站名和观察日志的文字停在 4.0 上下，**没到 4.5**，这轮是明知故犯：它们是 15px 签名和 13px 标签，不是要读三遍的正文。再往上推只有两条路，都写在这里备用——

- 提 `--scrim-mid`（亮色 `.14` → `.20`+）：代价是照片中段起雾，而那一段正是晨光最亮的地方；
- 给这两行垫一层玻璃面：代价是首屏多出两块可见的框，§5 的"从雾里走出来"变成"从玻璃后面走出来"。

⚠️ **纵向 stops 这轮改了：`0% 顶 / 35% 中 / 62% 中 / 97% 底` → `0% / 35% / 68% / 100%`**（2026-09-27 第三轮）。理由不是审美：那条"在 97% 处溶成 `--bg-base`"的斜坡，职责是**把首屏照片接进它下面的实色内容区**——而 `.ending` 撤掉之后首页只剩一屏（`scrollHeight == innerHeight`），下面没有内容区了，斜坡便只把这一屏的下 1/3 抹成一块纯色，正是这轮要撤的东西。现在照片一直留到 68%，只在最后 32% 里溶掉，落点仍是 100%＝视口底（**斜坡必须真的走到底**：视口太矮、首页溢出而能滚的时候，`.scene` 之外露的是实色 body，落点不到底就会在 100vh 处切出一道硬边）。

⚠️ **第四轮之后这条斜坡重新有了它名义上的那份工作**：首页下面接了实色内容区（§4 / §15），"把首屏照片接进它下面的实色区"从一句只对"视口太矮"成立的话，变回对全站成立的事实。上一段里那句"下面没有内容区了"因此是**当时的现场记录**，不是永久状态——留着它是因为它记下了一件事：**撤掉一个元素和撤掉一个现象不是一回事**，`.ending` 撤了、那条纯色却还在（它由斜坡产生），而真正的缺口是"首页没有内容"。stops 的数值这一轮**一个字都不改**：`.scene` 仍旧 100vh、落点仍旧 100%，改的是它下面有什么。

**照片使用铁律：**
1. 照片只允许出现在**首屏背景**和**内容位**（封面/截图/人像），不允许出现在其他区块背景
2. 首屏背景照片必须带纱罩——原图直出会打破同族色纪律、吃掉文字对比度
3. 文字可读性靠三层保障：纱罩 + 文字光晕（`--halo` text-shadow）+ 首屏信息量层级。⚠️ **"暗色沿用了亮色那层纸白 halo"这条不成立**：`--halo` 本来就分主题（亮 `rgba(242,244,239,.55)` / 暗 `rgba(14,19,13,.6)`，home.css 与 mistwood.css 各一份且取值一致）。逐像素验过字形外那一圈（覆盖率 .02–.30、74368 px）：**94.9% 的像素是变暗的**，平均 Δlum −0.0104 ⇒ 暗色那圈是**暗光晕**，不是白毛边。 perceived 白边另有其因（浅色字形在中间调底上的抗锯齿，加上暗光晕把周围压暗后的对比错觉），要治的是 `text-shadow` 的模糊半径，不是颜色
4. 场景层高度 = 100vh。⚠️ 这条原本带的半句"照片随滚动动线自然离场，下方内容落在实色 `--bg-base` 上"在第三轮一度只对"视口太矮、首页能滚"的情形成立（首页当时没有下方内容），第四轮补回内容区之后**它对首页也恢复了效力**——`.scene` 之外仍旧是实色 body，只是现在那儿真的有东西（§15）

⚠️ **"标题右半压在最亮的雾上"——实测方向是反的**（2026-09-27，两帧只差文字、逐像素、531×559）：暗色标题**左半**中位 6.63、只有 37.3% 过 7:1，右半中位 7.46、72.6% 过线；亮色同样左强右弱（11.89 / 9.58）。标题区背景亮度按横向三分的中位数：暗 **左 .076 · 中 .069 · 右 .059**，亮 **左 .83 · 中 .73 · 右 .58** ⇒ **这张裁切里那片亮雾在左不在右**，所以 `--scrim-text` 的 `22% 60%` 中心没算错方向，**不动它**。⚠️ 这条只在**这个视口**成立：照片是 `object-fit:cover`，宽屏裁的是另一条横带，"好文章压在亮雾上"在 1440×900 完全可能成立——内置浏览器改不了窗口尺寸，**没在宽屏量过之前不许按这条挪遮罩**。真要动，先量左半（它才是这个视口里弱的一侧），且 42–68px 属大字档、地板 3:1，两侧都还守着。

**滚动叙事弧线**：首屏雾最浓（照片 + 雾带）→ 越往下内容越实（实色底 + 玻璃卡）→ ⚠️ 第四轮起**第三拍回到首页**：由最新一条 note 收尾（日期＋一两句话，页面最后一段文字，它下面只剩 22vh 留白）。第三轮撤掉 `.ending` 之后这一度只剩两拍、"散开"交给子页开场那层气（§15）去做——那是**把缺的那一拍转记到别的账上**。现在两件事各归各位：子页开场那层气管"进场"，首页最后那句话管"离场"。
⚠️ 第三拍的载体必须是**作者真写过的一句话**，不是浮动出来又消失的短句池：随机抽来的"雾又合上了"读起来像人格，实际是生成的（§7 的铁律是所有数字与句子都对应真实内容），而且 2s 就消失的文案对读者不公平——他刚看清它。notes 数组里现成就有，取最新一条常显即可。
"从雾里走出来，看清一些东西，再走回雾里。"

- ⚠️ **那枚状态点外面多了一圈"苔时弧"**（第四轮）：实心点仍旧是"现在"，外面那条 15px 的弧是"今天已经走完的这一段"——一天 24h 走一圈，起点在 12 点方向，`--moss` 描边、opacity .42、只画走过的部分不画整圈刻度。它**不是动效**：动的是 `stroke-dashoffset` 这个属性值，随 15s 一次的 tick 更新，没有 `animation`、没有 `transition`，所以"时钟零动效"这条一个字没让步（口径和 §15 那条"气带是静态渐变所以不占常驻预算"同一族）。为什么不做成独立的一枚小表盘：那等于让"点"和"弧"两个图形说同一件事，而 §9 上一轮刚为"同一个符号两种状态"把当前页的下划线换成了点——**这里反过来做：同一个图形担两层信息**。周长不写死在 CSS 里，由 `getTotalLength()` 从几何本身要（写两处迟早分叉）。窄屏 `.nav-clock` 整条隐藏，弧跟着消失。
- ⚠️ **"守夜"是人格层，不是色温层**（第四轮）：`night` 时段第一次落进本站时，首页观察日志下面多一行 `守夜`（11px 等宽、字距 .3em、`--ink-3` 装饰档、压双层光晕）。三条口径：① **落点不在导航**——`mistwood · fog` 那一串是英文标签层，往里插中文正面撞 §7"两层各管一种语言"，而且那格三个字段已经是信息上限、窄屏还整条隐藏；② **一次会话只播一回**（`sessionStorage` 记 `mistwood-greeted`，刷新即无），读不到 session 就永远不显示，不猜；③ 它跟着 `phase==='night'` 走而不是跟着"20:00"这个常量走——傍晚窗口已经换季了（§2.3），"入夜"从此是一个季节量。这一行是首屏信息层级的第 4 级（§10.4 那三档之下），删掉不丢任何信息。
- ⚠️ **第五轮：那一格从"守夜"一个词扩成三个词**（`site.js` 的 `WATCH_WORD = { night:'守夜', dawn:'初', dusk:'暮' }`）——**一格、一套机制、一枚 `mistwood-greeted`**，`index.astro` 里那个 `<p>` 从此不带文字，词由脚本按 `phase` 填。三条口径：
  - **清晨与傍晚只给一个字**。"初""暮"是"你来得正好"这一档招呼，再长就要造句，而造句一旦从池子里来就撞 §12 那条"随机短句池当人格"。"守夜"仍旧是三个字里唯一说整段的——因为它担的是"这个点还亮着灯"这件具体的事。
  - **`day` 时段这一格是空的**：不填"午安"。一天里有一半时间什么都没说，这一格才读得出它是**跟着时刻长的**，不是常驻问候语。
  - **`hidden` 由脚本决定，静态 HTML 里永远是空的**（原先前一轮写死 `守夜` 再靠 `hidden` 藏，等于把一句话印在模板上再遮）；读不到 `sessionStorage` 就永远不说，刷新即无——一条没变。
- ⚠️ **真实月相，做成环境光不是图标**（第五轮）：`site.js` 用平月法算月龄（`SYNODIC = 29.530588853` 天，新月基准 2000-01-06 18:14 UTC），落在满月 **±1.2 天**内就给 `<html>` 挂 `data-moon="full"`，其余时间**这个属性根本不存在**（不是 `data-moon="new"`——没有观测就没有声明）。它改四处，全在夜林里：`--shadow` 走到 `0 16px 30px -10px rgba(14,19,13,.62)`（无月之夜本来就该没方向光，有月的晚上影子回来了）、雾灯半径 ×1.09、那圈月光晕从 `1.15×r / α.12` 放宽到 `1.2×r / α.16`、时钟那枚 5px 实心点与苔时弧换成 `--moon`。三条要交代：
  - **精度**：平月法不是真天象，与真满月最大差约 ±0.6 天。实测对账——2026-09-26 的真满月发生在 16:49 UTC，本模型的峰值在 23:00 UTC，差 6 小时，落在窗口内。**为什么仍然不引星历表**：VSOP87 那类要几百行还要处理时区，换来的只是"亮一档"这个感觉；更关键的是**语义**——这一档说的是"这两天月亮圆着"，页面不写"满月"两个字、不给月龄数字，一旦给了就要为分钟负责，那正是 §2.3 否决节气上导航的理由。
  - **α ≤ .12 那条例外是登记过的**：§8.5 的"暗色光晕月光色 α ≤ .12"从此写作"满月那两晚到 .16"。**只由月相触发、用户不能拧**——抽屉那四枚旋钮管不到它，枯草金那类外来光色仍旧禁止。
  - **它不进 §2.4 那笔账**：照片底与纱罩一个字没改（暗色标题中位 6.81、≥7 只有 44.5%，全靠大字档 3:1 守着，提底就是找死），改的全是投影、灯和两枚装饰点 ⇒ 已登记的可读性数字一个都不用重测。门禁照旧把它当一档跑（六档，§2.4）。
  - **亮色没有月亮**：`data-moon` 的块全部带 `data-theme="dark"`。夜林的身份证是"无月之夜"（§2.2），满月那两晚它是**另一个夜林**，不是"夜林加个滤镜"。
- 天气词驱动时段色温（见 2.3），⚠️ 第四轮起**傍晚窗口随月份走**（年循环套日循环）
- 访客应感觉"今天早上来和下午来不太一样"，而不是"这网站会变色"；⚠️ 年循环那一层的判据同句成立——"今天和半年前的今天不太一样"，不是"网站换了时刻表"

## 7. 观察日志文案系统（人格层）

- 首屏：`03 essays · 04 things · 03 notes`——等宽数字 + 全小写宽字距
- ⚠️ **这一行的下面就是那三篇的名字**（第四轮，见 §15"首页下半段"）：观察日志报数、内容区报名字，两层是同一句话。所以新加的那一段不引入第二种语气——标题仍旧 `recent essays — 03 →`（§7 的"区块标题旁统一为 `essays — 03 →`"这一形），行仍旧是 §15 的目录行，日期与分钟数仍旧构建期真算。**日志报的是数组长度，内容区列的是数组元素，两处都从同一份 `getCollection('posts')` 来**，写不出不一致
- 区块标题旁统一为：`essays — 03 →`、`things — 04 →`、⚠️ `notes — 03 →`（三种同形，别再出现"观察日志 · 03 collected"这种混排）。`about` 没有对应数组，页头就**不放**标签——硬凑一个数字等于撞 §12 的假数字

- 关于页底部：`last walk · 2026.09.25 · weather: light rain`——给用户手填的位置（⚠️ 原先在页脚；搬到 `--bg-top` 最浅处实测 4.89:1，所以颜色从 `--ink-3`(2.30:1) 提到 `--ink-2`，12px 信息文字够不到 §2.4 的 4.5:1。⚠️ 这个读数随 `--ink-2` 第五轮换值一起换算，见 §2.4）
- ⚠️ **详情页那一行"写于一个九月的深夜"**（第五轮）：front matter 多了一个**可选第五键 `hour`**（0–23），月份从 `date` 推是事实，**小时只能来自写的人**。`[slug].astro` 的 `whenOf()` 把它映成七档：清晨 05–09 / 上午 09–12 / 正午 12–14 / 下午 14–17 / 傍晚 17–20 / 深夜 20–24 / 凌晨 00–05。**空着整行一个字都不出现**：`date: 2026-09-05` 里没有小时，编一个是给文章伪造写作时刻——§12 假数字的近亲，**假语境**。⚠️ 空值这条路踩过实坑：`z.coerce.number()` 会把 YAML 里空着的 `hour:` 和 `hour: ""` 都铸成 **0**，页面于是宣称"写于一个九月的凌晨"，所以 schema 前套了一层 preprocess 把 null/空串退回 undefined（两侧都验过：填 `hour: 21` ⇒ 落"深夜"、空着 ⇒ `dist` 里 `post-when` 零命中）。
  - 排印落点是独立一行 `.post-when`（14px 宋体 `--ink-2`，§3 的"说明"档），**不并进 `.post-meta`**——那一行是 IBM Plex Mono 的英文标签层（`09.12 · essay`），塞中文会掉进字体回退、同一行两套度量。与 §7"两层各管一种语言"同一个理由。
  - 它和 §6 那三个词是同一层事：一句话说"你在什么时候读"，一句话说"写的人是在什么时候写"。**两边都不给分钟**——分钟归时钟那一格，那是全站唯一承诺分钟级真实的地方。

## 8. 动效系统

### 8.1 缓动三档（不许发明第四种）

| 档 | 气质 | 用途 |
|---|---|---|
| 吐纳 | `cubic-bezier(.22,1,.36,1)` 先快后极慢 | 所有入场、悬停位移、颜色/透明度反馈、主题切换 |
| 回弹一点 | ⚠️ `cubic-bezier(.24,1.32,.4,1)`（过头约 4%） | 只给**按下**——`:active` 的 0.98 缩放。卡片上浮走吐纳，两档别混用 |
| 匀速 | linear | 进度线 + 无限循环装饰（雾带、萤火虫、"现在在做"呼吸点） |

⚠️ 浏览器默认的 `ease` / `ease-in-out` 就是第四种缓动，属 §12 禁区——这轮把三处文件里 30 多个 `ease` 清零了。`steps(4)` 只许出现在颗粒上。

### 8.2 Hero 入场时间轴（共 ~2.4s，像一口气慢慢吐出来）

| 时刻 | 事件 |
|---|---|
| 0.0s | 只有渐变底和雾 |
| 0.2s | 名字浮起淡入（12px，0.7s） |
| 0.45s | 标题按**词**浮起：8 个词单元，词间隔 50ms，每词 0.7s 吐纳（词内 mask 升起） |
| 1.4s | 导航玻璃条落下 8px 淡入 |
| 1.50s | 斜体词最后落地（单独淡入 1s，像特意停顿后才说出口）——第 8 个词恰好也在 1.50s 收口，句子说完和"light"开口是同一刻，不抢拍 |
| 1.2s | ⚠️ 照片底开始淡入，2.2s 走完（最慢的一组，3.4s 落地） |
| 3.4s | ⚠️ 进入常驻状态：雾带漂移，夜里萤火虫上岗（旧版的"三排林线 + 光斑 + 滚动提示"随照片底方案退场） |

⚠️ **回访版：第二次之后不再让人等第二遍**（第四轮）。上面这张表用 `getAnimations()` 实测过每条一次性动画的落点：词 1150–1500ms、导航 900ms、日志 1600ms、斜体词 **2500ms**、照片 **3400ms**——**2.5s→3.4s 那 900ms 里屏幕上只有照片在变可见，文字早就说完了**。所以"入场 3.4s 是等待"这句判断，等待全部来自最慢的那一组，而不是来自按词错落。
于是只动一组：`html[data-revisit] .bg-photo{ animation-duration:.8s; animation-delay:.2s }`，照片 1.0s 落地，整场收在 2.5s（斜体词那一拍）。**词的 50ms 错落一点都不压**——那是这套排面的身份，而且上面 1.50s 那条"句子说完和 light 开口是同一刻，不抢拍"的对齐就挂在它身上，压错落等于作废一条已登记的判据。
三条实现口径：① **判据是"本次会话看过完整入场没有"**（`sessionStorage.mistwood-seen`），不是 `mistwood-opens`——那个键站内跳转也算一次（§15），分不清"刚进来"和"翻了个页"；② **判定必须写在 `<head>` 的内联脚本里**，晚一步（等模块脚本）照片已经开始 2.2s 的淡入，改了也看不见；③ **用户可关**：抽屉第四枚旋钮"入场"（自动 / 完整），选"完整"就不走这条捷径——"设计如此"要配一枚能拧的开关。顺带一条与 §8.3 的耦合：`speculationrules` 预取成功时新文档**本来就已经就绪**，那时还重放 2.4s 入场不是仪式，是 bug——预取越准，这一档越该在。

⚠️ **mask 的粒度是"词"不是"行"**（2026-09-27 改）。原来一行一个 `overflow:hidden`，窄屏 44px 下第二句必然折行、两视觉行会一起升还甩孤行，当时靠"降级成整行淡入"绕过。现在词盒本身是 mask 单元（`white-space:nowrap` 保证一个词不拆），折行天然发生在词边界，每个词各自升起——**降级分支已删**，窄屏只留 `text-wrap:balance` 收拾视觉行的配比。
⚠️ **首屏的垂直节奏**（2026-09-27 第三轮）：名字钉在 `margin-top:17vh`（整组居中时它原本落在 16.8vh ⇒ **标题一行都没挪**，实测 151→151、盒高 178→178），日志改成 `margin-top:auto` 沉到视口底上方 `8vh`。原先三件一起居中，得到的是"标题 + 44px + 日志 + 162px + 底"——第二段空白什么都不承担；现在日志是这一页的**最后一行**，顺手替首页做"往下走"的引导。⚠️ 另一条引导方案（竖线向下延伸）**在这张图上不成立**：这张照片的构图是向上生长的（树干垂直、树冠在上、光从上来），任何向下的动线都是硬加的，要用就得换一张有下坡/水面的图。
⚠️ **斜体词左右各 `.12em`**：Fraunces 斜体直接挨着中文会贴死（"light和"）。这 .24em 是**占行宽**的，所以改完复测了标题盒总高（178px → 178px，没有多折出一行；531px 视口下第二句本来就折两视觉行）。至于斜体造成的"light 略往下沉"——**留着不校正**，它正好呼应上面 1.50s 那次"特意停顿后才说出口"。
⚠️ **词盒的 padding 不是装饰**：左右各 `.35em` + 等量负 margin 是给 28px 光晕留裁切余量（`overflow:hidden` 连后代文字的 `text-shadow` 一起裁，贴着字形裁会切出方形硬边）；纵向 `.18em`/`-.18em` 让 descender（`light` 的 g）不被裁，同时**不还进行高**——原子行的行盒按 margin box 算，负 margin 正好抵掉 padding。实测：mask 版与"去掉 mask"对照版 h1 总高同为 177.55px，68px 桌面下两视觉行行距 89.75px = `line-height:1.32` 原值，词与词之间零额外间隙。
⚠️ reduced-motion 必须显式给 `.w > span` 写 `transform:none`：词盒的**静止态就是 translateY(112%)**，只 `animation:none` 会把标题整块留在 mask 外面（看不见等于没降级）。

### 8.3 交互反馈

- **悬停卡片**：上浮 4px + 投影离地 + 图片放大 1.03（0.5s 吐纳），三属性同时但极轻——"凑近看"。⚠️ 这轮补齐：投影落在 `.cover`（离地的是那块面，透明卡体上打影没有意义），图片 `scale(1.03)`；列表卡从 `<article>` 改成整卡 `<a>`，悬停反馈和点击范围从此是一回事
- **悬停链接**：导航链接下划线从左长出 2px 苔绿；正文链接**下划线加深 + 变粗 1px**（不做滑入，太常见）。⚠️ 已落地（`/essays/<slug>/` 的 `.post-body a`）：静止态 `--moss-ink` + 1px 下划线取 40% 透明度、`text-underline-offset:3px`，悬停时颜色补满、厚度 1px→2px，0.3s 吐纳。⚠️ "长出"那一下现在走 `transform:scaleX(0→1)` + `transform-origin:0 50%`（原来是动 `width`，见 §8.8 属性口径）——读感不变，悬停不再触发重排
- **悬停目录行**（2026-09-27 新增，`/essays/` 的 `.row`）：整行右移 6px（`transform`，不动 padding）+ 编号转苔绿 + 摘要 `opacity 0→1`，**恰好三个属性**（§1 预算上限）。摘要那两行的位置平时就占着（`min-height:3.4em`），所以显形不引起任何重排
- **按下**：下沉 1px 或缩放 0.98，带 3–5% 回弹；**不做涟漪**（太 Material）。⚠️ 已实现：`:active` 缩放 0.98 + 回弹档，落在主题切换钮、文章卡、图鉴卡、关于页联系方式、上下篇
- **页面切换**：旧内容 0.4s 淡出上浮 8px → 新内容 0.5s 下方淡入，不做花哨转场。⚠️ **已启用**（2026-09-27）：`@view-transition{navigation:auto}` + `::view-transition-old/new(root)` 两条关键帧，零 JS，跨文档同源跳转由浏览器接管快照。实测同文档 VT 下两条动画分别在 400ms / 500ms 收口。三点登记：
  - **两段同时起跑**，不是严格串行（浏览器只给一个快照窗口，串不起来）；位移 8px / 10px 按同一速度 20px/s 配平，读起来才不像两个节奏
  - **fill-mode 必须 `both`**：新内容多出的那 100ms 里，旧快照按默认 `none` 会回填成不透明，末尾闪一下
  - **`prefers-reduced-motion` 要单独掐**：转场伪元素树不在文档树里，全局那条 `*{animation:none}` 管不到它
  - 生效范围：Chrome / Edge（本机 Chrome 150 实测）。Firefox、Safari 认不出这个 at-rule 与这组伪元素，退成瞬时导航——就是本条启用之前的现状，不引库兜底
  - ⚠️ **配套开了原生预取**（`<script type="speculationrules">`，`eagerness:conservative`，同源 `/*`）：转场要求新文档在快照窗口里已经就绪，否则浏览器只能放弃动画走瞬时导航。预取零 JS 代码，conservative 保证不会一进首页就把五个页面全拉下来
  - ⚠️ **第五轮：两段之间插进 80ms 的"翻书停顿"**。改的只有一处——`::view-transition-new(root)` 的动画加 `animation-delay:80ms`，**`fill-mode` 仍是 `both`**（默认 `none` 会让那 80ms 里新内容直接可见，停顿就变成"先闪一下再淡入"）。全程 580ms：旧页 400ms 收口，新页 80ms 起跳、500ms 走完，两段各自都还在 §8.3 的 0.3–0.6s 交互档里。⚠️ **关键不在 delay，在中间那层得有东西**：跨文档转场的伪元素树是盖在**已经渲染好的新文档**之上的快照，两层都透明时露出来的是"下一页"、不是雾——所以必须先给 `::view-transition-image-pair(root)` 铺底，铺的就是子页 body 那条 40vh `--bg-top`→`--bg-base` 渐变（§15）。顺带的效果：交叉淡化中点也会透出一点地面，转场中途起一层薄雾。⚠️ Chrome 给 `::view-transition-new` 的默认 `mix-blend-mode` 是 `plus-lighter`，所以"透底"透出来的是加亮、不是盖白。代价：**多一个伪元素的背景绘制**，且这 80ms 在慢机器上会让"下一页来得更晚"一点——读起来是"翻了一页"，不是"卡了一下"，这条要靠眼睛判。**本网络/本机测不了它顺不顺**：内置浏览器 `visibilityState=hidden` 时 CSS 动画不走帧（§8.2 那条老坑），所以这 80ms 只有"三条规则都进了产物"这一层是实测的（`dist/_astro/*.css` 里 `image-pair` / `old` / `new` 各一条），**手感待用户在默认浏览器里看一次**。
- **主题切换**："日出/日落"——背景 0.8s 先变，文字延迟 0.15s 跟上，光斑最后淡入。⚠️ 实现为"背景/文字同批 0.8s 吐纳 + 两张照片 0.8s 交叉淡化"；"光斑最后淡入"随光斑一起退场

### 8.5 雾灯 Cursor Lantern（首屏鼠标交互）

> 2026-09-27 新增。首屏此前只有隐性的全景视差，缺一个"鼠标是参与者"的交互；雾灯 = 光标提着一盏看不见的灯，照亮处雾散开。

- **机制**：纱罩 scrim 上以灯位为心开一个"洞"（mask 径向渐变：中心 4% 可见 → 72% 处完全恢复），照片在洞里露出原本的清晰度。灯位 lerp 0.06 迟滞——**灯总比手慢半拍**，与吐纳节奏一致
- ⚠️ **半径是一个 token，不是写死的像素**：`--lantern-r:clamp(140px, 22vmin, 300px)`（2026-09-27 第三轮）。原先四处写死 `200px`/`230px`，等于"灯只在 1440×900 上是对的"——小窗与笔记本上洞占屏过大，大屏上又过小。22vmin 在 1440×900 上正好回落到 198px ≈ 原值，所以**这次改动的基准视口上画面不变**，变的只是两端：

  | 视口 | vmin | `--lantern-r` |
  |---|---|---|
  | 531×559（内置浏览器实测） | 531 | **140px**（撞地板） |
  | 1024×768 | 768 | 169px |
  | 1440×900 | 900 | 198px ≈ 旧值 |
  | 1920×1080 | 1080 | 238px |
  | 2560×1440 / 3440×1440 | 1440 | **300px**（撞天花板） |

  地板 140px：再小就不像一盏灯而像一个噪点（⚠️ 第四轮起触屏另有一档 96px 地板，见下面"触发"那两条）；天花板 300px：再大就等于整块纱罩被掀开，"提灯"变成"没有雾"。
- **暗色光晕按比例挂在这个半径上**：`calc(var(--lantern-r) * 1.15)`（旧值 230/200 那个关系），所以灯放大时那圈月光跟着放大，不会脱开洞沿。实测三处一起解析：mask `140px` / rim `140px` / glow `161px`（531×559 下）
- ⚠️ **洞的开合度是一个注册属性 `--hole`**（`@property syntax:'<number>'`，初值 1 = 雾合上）。必须是可插值的数字而不是写死的 `rgba(0,0,0,.04)`：mask 里的颜色 stops 不可过渡，若只淡 rim/glow，熄灯时会留下"白环还亮着、洞已经合上"的半截灯。不支持 `@property` 的浏览器退化为瞬开瞬合（rim/glow 仍是淡出的），可接受
- **浅色 = 日照穿雾**：洞内照片变清晰本身就是奖赏，**不加任何光色**；洞外沿叠一圈极淡白环（雾被挤到光圈外沿）
- **暗色 = 手提雾灯**：同一个洞 + 一层月光色（`--moon`，α ≤ .12）径向微光——暗色照片照穿后仍是暗的，需要光源感才读得出"灯"而不是"洞"
- **会熄**：光标停止 **700ms** 即熄（`--hole` 回 1 + rim/glow 淡掉），离开窗口立刻熄；再动手重新点亮。**熄 0.9s / 点 0.6s 是不对称的，且熄得更慢**——这是有意偏离 emilkowalski"退场快于入场"的一条：那条管弹窗跟手感，这里管氛围收束，"雾重新合上"不该比亮起来急
- **预算**：不占常驻动效名额（无鼠标时灯不存在，不渲染；空闲 700ms 自动退场，屏上不会留着它）；与全景视差共用一个 rAF 循环；随场景层 100vh 滚出自然离场
- ⚠️ **触发从一种变三种：降级不等于缺席**（第四轮）。原先这条写的是"仅 `pointer: fine`，移动端与键盘访问者面前它不存在"——最惊艳的交互全部只属于鼠标，手机与键盘用户拿到的是减配版。现在：
  - **鼠标**（`pointer: fine`）：跟手，lerp .06 慢半拍，空闲 700ms 熄，离开窗口立刻熄——原样不变。
  - **触屏**：**按住即亮、松手即熄**。刻意**不跟手**：跟手要读 `touchmove`，那正好和滚动抢同一根手指；按住不动的那一下才是"提灯看"这个动作本身。不 `preventDefault`（`passive:true`），滚动照滚；手落在导航/链接上时不点亮（那是按钮不是灯）；只在首屏那 100vh 内响应（下面没有纱罩可拨）。
  - **键盘**：**Tab 到哪，灯照到哪**（`focusin` 取元素盒中心，`focusout` 且焦点没落在同组可聚焦件上就熄）。灯的本意是"指向"，而焦点就是一次指向——这条路比"给键盘用户一个替代动画"更贴原设计。两枚链接之间移动不熄（`relatedTarget` 还在范围内就跟着走）。
  - 三条都不与 §1 常驻预算打架：无输入时灯不存在，不渲染、不占 rAF（触屏与键盘那两条**根本不进 rAF 循环**，就地落位）。reduced-motion 仍旧一律不上岗。
- ⚠️ **半径的地板按指针类型分两档**：细指针 `clamp(140px, 22vmin, 300px)`（原样），**粗指针 `clamp(96px, 26vmin, 300px)`**。理由是 140px 那个地板的前提（"再小就不像一盏灯"）是拿鼠标屏的尺寸说的；390px 宽的手机上 22vmin 撞 140px 地板＝洞直径占屏 72%，那不是提灯是掀罩。26vmin 在 390px 上≈101px，占屏约五成，还读得出"一处比周围清楚"。天花板两档共用 300px。
- ⚠️ **"拨雾"并进这枚灯，不做第二枚灯**（第四轮）。原提案是"悬停导航时它背后的雾局部变淡"——机制与雾灯完全同一件事（以光标为心把纱罩开个洞），只是半径更小，等于给首屏装两枚跟随光标的灯，读起来是二重奏。改成：**灯照到导航那一段时，那层玻璃稍微变实**（`.nav.lit{ background:var(--glass-lit) }`，一枚灯、两种被照到的材质）。三条理由：① 只翻一个类，动的是 `background-color`——**§8.8 白名单一个字都没扩**（不新增可 animatable 的属性、不碰 `backdrop-filter`、不引第四种模糊）；② 复用 `.nav` 已有的那条 `.8s` 颜色过渡，落在"氛围响应"档而不是"控件手感"档，这是有意的；③ 判定"照到没有"用的半径**从 CSS 读**：`--lantern-r` 这轮注册成 `@property syntax:'<length>'`，`getComputedStyle` 拿到的就是解析后的 px（实测 531×559 下返回 `140px`），JS 不必重抄一遍 `clamp()`——半径的真值仍旧只有一个。⚠️ `prefers-reduced-transparency: reduce` 下这一下不响：那条把 `.nav` 的背景钉成 `--surface !important`，材质整个退回实面，本来就没有"照穿"可言。
- **禁区补充**：雾灯不许引入第三种光色（枯草金不行，会破每屏 2 处上限）

### 8.6 惊起萤火虫 Startled Fireflies（彩蛋交互）

> 2026-09-27 新增。与雾灯共存的"生命感"彩蛋：萤火虫不是贴图，是会被手惊动的小东西。

- **触发**：光标速度 > 1.2px/ms（快速划过）且距萤火虫 < 130px；**慢速靠近不触发**——鼓励轻轻地动
- **时序**（共 ~4s）：原地冻结 → 0.25s 熄灭 → 弧线逃逸（1.4s 吐纳，背离光标 60–110px、略向上 30px）→ 逃逸途中重新亮起（0.8s）→ 隐去并回到原有明灭节律。⚠️ "弧"是两段拼出来的：0.5s 横着弹开（走 72% 位移、30% 上扬）+ 0.9s 继续飘出去并上抬——单段直线只是"逃"，两段才有"弧"
- **上限**：同屏至多同时惊起 3 颗；惊起中的萤火虫有 4s 冷却，不会被打断第二次
- **预算**：事件驱动，非常驻；与雾灯/视差共用一个 rAF 循环
- **缺席即合理**：只在萤火虫在岗时存在（暗色 / 亮色深夜）；亮色白天没有它，不补假货

### 8.7 内容区滚动入场

- IntersectionObserver（threshold .15）触发：升起 16px + 淡入，0.8s 吐纳，**只演一次**（unobserve）
- 同帧进入视口的元素错落 80ms——像目光扫过去依次看清，不是整板拍上来。⚠️ 2026-09-27 起**节拍住在 CSS 里**：`.reveal{transition-delay:calc(var(--cascade,0)*80ms)}`，`site.js` 只负责把序号写进 `--cascade`（原来 JS 直接算 `transitionDelay` 毫秒数）。这样"80ms"这个值只出现在规范与 CSS 两处，不再散进脚本——与 Hero 标题的 `--i`（§8.2）是同一套机制，一处序号两种动效
- reduced-motion：直接落到终态，无位移
- ⚠️ **归巢**（第四轮）：从 `/essays/<slug>/` 返回列表时，之前点进来的那一行**门牌亮一下再落回**——`.folio` 从 `--moss` 走到它的静止色 `--ink-3`，1.6s 吐纳、前 30% 亮住（"亮—落"两拍，全程在 §1.3 的 1s 地板之上，读起来是回位不是闪）。四条口径：
  - **符号不用下划线**。那条 2px 苔绿短线是"悬停"的记号，§9 上一轮刚为"同一个符号表达两种状态"把当前页改成点——同一个错不能犯两次。编号是这一行的**门牌**，门牌亮一下＝你回到这个门口，它不携带别的语义。
  - **终态颜色＝静止颜色**，所以 `animation:none` 直接就是正确落点，不会卡在亮着的苔绿上（这条是 §8.2 那条"词盒静止态本身就是 translateY(112%)"教训的正向用法）。
  - **挂 `pageshow` 不挂 `DOMContentLoaded`**：§8.3 的预取与 bfcache 会把文档原地复活，那时后者根本不再触发——而"回来"恰恰是这条交互唯一的场合。实测：写标记→`pageshow`→`.row.homing` 出现、`folio` 颜色 124,154,128 → 154,165,155、标记清空 ✓。
  - 标记只在详情页写、只在**找到那一行**的页面上清；中途绕道去 `/about/` 不算丢，下一次落在有它的页面上照样亮。路径匹配用 `dataset.slug` 逐项比对，不拼进 `querySelector` 的选择器串（`sessionStorage` 的值来自 URL，别给自己留注入面）。

- ⚠️ **身后的雾：走过的路自己淡进雾里**（第五轮，详情页）。`.post-body` 上挂一条滚动驱动的 `mask-image`——雾线钉在**视口 30%** 那一行（阅读位置之上），它以下完全不动，往上走 100vh 才淡到底（地板 α `.56`，深度 `min(.44, .44 × --fog)`：淡档 `.176`、中/浓档夹在 `.44`）。`--read-fog` 由 `site.js` 在**进度线那个同一个 rAF 回调**里写，零新监听、零新循环；`--read-fog` 起始 `-9999px` ⇒ 一进页面整段全实。四条口径：
  - **是"字自己在身后化掉"，不是"给屏幕加一层纱"**。加一层纱会蒙在正在读的字上，§2.4 那笔按纯色底算的账当场作废——和 §15 那条"气必须在 `z-index:-1`"是同一个理由。mask 只作用于正文自己这一层，`--bg` 与玻璃导航都不参与。
  - ⚠️ **坡道起点钉在雾线上游 100vh，不是元素顶**（这条是本轮实测改的）：钉元素顶时屏顶那行正文会一路掉到 **2.34:1**（亮色 `--ink`），那是 §2.4 明令的"正文淡是事故"；钉在雾线上游之后坡道在屏幕上是**恒定**的——屏顶 5.05、到 30vh 回到 13.13，数字逐档登记在 §2.4。**"走过越远、淡得越多"因此是一个屏幕量，不是一个文档量**，这才对：读者参照的是自己眼前，不是这篇有多长。
  - ⚠️ **深度上限由 `min()` 夹住，不给浓档放行**：`--fog` 1.35 会把地板推到 `.487`、屏顶掉到 4.2 以下 ⇒ 一个氛围旋钮作废 §2.4 的地板。夹住之后浓与中在这一层同值（实测三档：淡 .947 / 中 .868 / 浓 .868），**这是有意的不对称**，与"纱罩不吃 `--fog`"（§15）同族。
  - **两个开关都在**：`prefers-reduced-motion` 下 `-webkit-mask-image:none`（滚动驱动的"动"正归它管，撤掉之后文字回 100% 实）；抽屉"雾＝淡"把屏顶抬回 **8.01**，够正文 ≥7 那一档。**代价写在 §2.4**：顶端那一段是氛围档，不在 7:1 里。
- ⚠️ **合上书＝更静，不是更响**（第五轮）：读到文末（`.post-body` 底边越过视口 82%）时给 `<html>` 挂 `data-quiet="1"`，颗粒那唯一还在动的常驻层用 `transition:opacity 1.2s` 慢慢退场；往回滚它自己回来。**反着做过的那一版否掉了**：文末把颗粒加深一倍——颗粒是 `position:fixed` 的全屏层，它闪一下等于全屏幕动一次，正面撞 §1.2"一处动处处静"；而"结束"这个感觉本该是一次沉默，不是一次响动。三条技术口径：① 只动 `opacity`（§8.8 白名单内）；② `1.2s` 是吐纳档里最长的一档，比雾灯"熄 0.9s"还慢，因为这是**收灯**；③ 触发用的仍是同一个 rAF 回调里的 `getBoundingClientRect()`，零新监听。⚠️ 短文章 / 高视口下"文末"未必能滚到 82% 那条线（内置浏览器 559px 高时 `scrollTop` 被夹在 1200，`quiet` 就不会亮）——**这一格够不到是几何事实，不加第二种触发去补它**：为了"总能触发"而改用"滚动到底"会让首页那种一屏页也参与进来。

### 8.8 属性口径与两条系统级降级（2026-09-27 新增）

> 参照 emilkowalski/skills 的 `review-animations` 十条标准对过一轮，补我们规范里空着的三个维度。

- **能动的属性是白名单**：`transform` / `opacity` / `filter`（仅入场虚焦那一下，blur 必须 <20px，我们是 10px）+ `clip-path`。**悬停类反馈禁动 `width` / `padding` / `margin` / `left` / `top`**——它们是布局属性，每次悬停都重排。禁 `transition:all`（全站 0 处，已核对）
  - ⚠️ **第五轮把这条的口径说准**：白名单挡的是**重排**，不是"一切非合成属性"。`box-shadow` 是绘制属性——它不重排，但每次插值都要重绘那块阴影。全站现有**一处**在过渡它（`.thing:hover` 的 `transform .5s, box-shadow .5s`，图鉴卡离地那一下），本轮的"光的方向"（§2.3）**故意不**过渡它：时段切换是离散改值、一秒一跳。两者都成立，但要写清楚区别在"谁盯着看"——卡片阴影是手边 0.5s 的反馈，全站投影换档是没人正盯着的时刻发生的。⚠️ **新增一条纪律**：`--shadow` 现在是**四档值**（正午基准 + 清晨/傍晚/夜），谁将来要给它加 `transition`，先重读 §2.3 那条约束②。
  - ⚠️ **已登记的一处例外**：关于页联系方式 `.contact-links a` 悬停仍用 `padding-left:0→34px`。原因是苔绿小箭头 `::before` 绝对定位在盒子左端，要"文字右移让出箭头"又让箭头留在原位，改成 `translateX` 会把箭头一起带走；而用 `<span>` 包文字做位移会让链接命中区跟不上文字，反而缩小可点范围。**代价**：悬停那一下有一次局部重排（元素是 `width:fit-content` 的单列链接，影响半径仅限自身）
- **`prefers-reduced-transparency: reduce`**：全站 8 处玻璃模糊不是"装饰风格"而是**材质**，但系统级"减少透明度"偏好此前完全无响应。现在 `.nav` 与 `.thing-bar` 退回实色 `--surface` 并去掉 `backdrop-filter`——位置、层级、圆角、描边一概不变，只换材质。⚠️ 半透明**填充**（`.post-body code` 的玻璃底、封面占位的雾渐变）不属于该偏好要处理的对象，保留。⚠️ 这两条声明带 `!important`：首页 `.nav` 在 `home.css` 里另有一条 `backdrop-filter`，不加 important 就只能靠"Astro 恰好把 Layout.css 排在页面 CSS 之后"才赢——那是运气。用户偏好覆盖作者样式本就是 `!important` 的正当场景
- ⚠️ **压缩器会吃掉前缀对里的第一条**（实测 2026-09-27，Astro 用 lightningcss 压缩）：源码写 `backdrop-filter:X; -webkit-backdrop-filter:X;` 时，产物里**只剩 `-webkit-` 那条**，而无前缀版本被当重复声明丢弃——后果是**玻璃模糊在 Firefox 上从来没生效过**（Firefox 只认无前缀）。修法是把**无前缀那条写在最后**，产物即保留无前缀；代价是 Safari ≤17 拿不到模糊（退成半透明实底，仍可读，且 Safari 18 自 2024-09 起支持无前缀）。任何带浏览器前缀的属性都要按"标准在前、前缀在后"的直觉**反过来写**，或者干脆只写标准名
- **`prefers-reduced-motion` 的口径细化**：`animation:none` 与"infinite 一个不留"是 §1 的硬规定，不变；但**颜色与不透明度过渡保留 200ms**（`transition-property` 收窄到 `color, background-color, border-color, text-decoration-color, opacity`）。理由是主题切换承载"日出/日落"语义（§8.3），把它压成 0.01s 会让明暗切换变成**亮度突跳**——那正是 §12 禁的事。位移、缩放、模糊依旧一律归零

- ⚠️ **"现在在做"整行是可点开的披露件**（关于页）：原先那枚 5px 呼吸点纯装饰，现在 `<details>/<summary>` 包住整行（实测命中区 200×24，不是 5px），展开的是 **notes 最近三条**——"这一周在做什么"的答案本来就在日志本里，不新写一句。原生 `summary` 换来键盘、焦点、屏幕阅读器全套语义（同 §15 抽屉里那组真 radio 的取法）；⚠️ **默认三角 marker 撤了、不加光标**：加了箭头等于承认这行需要被解释，而 `now ·` 这个前缀本身就是解释。展开那一下 .4s 吐纳一次性，不占常驻预算；呼吸点仍旧 16s（全站唯一那枚子页面循环，§1 预算表登记的那条）。
- ⚠️ **404 是全站雾最浓的一页，但浓在背景不在功能**（第四轮）：`html[data-tier="lost"] .page-head{ --band-a:.95 }`——开场那层"气"的浓度从 look/read 两档的 .75 提到 .95，配上它最矮的带子（22vh），是一团压得低低的雾。**改的是 `--band-a` 不是 `--fog`**：后者是用户在抽屉里选的那一档，规范不许拿版面去覆盖偏好（而且 `html[data-tier]` 与 `html[data-fog]` 权重同为 (0,1,1)，谁赢要看打包顺序＝运气）。实测：`--band-a` 解析成 .95、雾档 `thin` 下计算出的 opacity＝.95×.4＝**.38**——用户的旋钮仍旧赢，这条是硬要求。⚠️ 地址列表**一条都不藏**：§15 那条"把真实存在的地址一次性全列出来"是刻意的，"光标接近才浮现出地址"是拿可用性换气质，键盘与触屏用户永远找不到——**气质走背景，功能走列表**。`prefers-reduced-transparency: reduce` 下这层气整个撤掉，404 的"浓"随之消失，那是那条偏好的正当后果。

## 10. 微交互细节（高级感的最后一公里）

1. 选中色 = 苔绿 20–25% 透明，不用系统蓝
2. 滚动条 = 6px 灰苔，悬停才变深。⚠️ 原来写的 `opacity:.5` 是死值——`::-webkit-scrollbar-thumb` 不支持 opacity，已删（§1.5）
3. 焦点态 = 苔绿 2px 描边 + 4px 偏移（键盘导航可见，无障碍即高级感）
4. 首屏信息量层级永远：简介 > 时钟 > 观察日志（后两者透明度依次降一档）。⚠️ 降档要降在能读的区间里：观察日志原先用 `--ink-3`，首屏实测 1.46:1（全站最低），现在它是 `--ink-2` + 双层光晕，数字部分用 `--ink`
5. 人像/照片入场前做褪色处理（降饱和 15%、提黑位）——**原图直出会瞬间打破同族色纪律**。⚠️ 具体值收进一个 token：`--photo-look`，亮色 `saturate(.85) brightness(1.04)`、暗色 `saturate(.8) brightness(.78)`（夜林要重新打光，不是反色），常驻在 `.cover img` / `.thing .shot` / `.portrait img` / `.post-body img` 四处，入场时再叠 `blur(10px)` 散开（§8.4）。⚠️ **第五轮它第一次落在真图上**（关于页头像）：那 15% 只把圆盘均值从 (143,127,145) 拉到 (147,133,149)，**对一张整体在 240°–360° 的图，降饱和救不了色相**——这条规则的"打破同族色"防的是原图直出的照片，不是作者本人的标识；实测数字与那枚没拧的旋钮都在 §13。

## 12. 禁区清单

- ❌ 纯黑背景 / 纯白卡片（永远带一点青绿倾向）
- ❌ ️ 纯黑阴影——暗色 `--shadow` 也用夜林色 `rgba(14,19,13,…)`，不用 `rgba(0,0,0,…)`
- ❌ 撞色、外来色相（紫、亮蓝、纯橙等）
- ❌ 第四种模糊、第四种缓动（⚠️ 浏览器默认 `ease` / `ease-in-out` 就是第四种）
- ❌ 涟漪动效、弹簧弹跳、1s 内的活泼动画
- ❌ ⚠️ `prefers-reduced-motion` 下还留着 `infinite`——哪怕时长被压到 10ms，那比不降级更闪
- ❌ 照片无纱罩直出 / 亮暗不同构图的照片对
- ❌ 照片出现在首屏背景与内容位之外的任何地方
- ❌ ⚠️ 占位提示压在真图上（封面/截图那类 `::after` 必须 `:not(:has(img))` 才成立）
- ❌ ⚠️ 死锚点：跨页导航只许指向真实存在的页面或锚点（首页拆过区块，`index.html#things` 这类地址已经不成立）
- ❌ 大写标签（全小写宽字距）
- ❌ 假数字、Lorem ipsum 式占位文案
- ❌ **随机短句池当"人格"**（第四轮）：光标离开首屏就浮出一句"雾又合上了"、2s 后消失、每次不同——这句否决写在 §5 第三条拍旁边。§7 的铁律是"所有数字与句子都对应真实内容"，从池子里抽的那句是**生成的**，不是作者说的；而且 2s 就消失的文案对读者不公平。要这一拍就用 notes 里真写过的那条，常显（第四轮已这么做）。同理，**随机频控**（"三次访问触发一次"）是机器特征，不是人格。
- ❌ **粒子化的点击反馈**（"拾叶"：点标题时飘起 3–5 片枯草金碎屑）。三条独立理由，任一条都够否：① §8.3 的"按下"槽位已经满了（每可点元素 1 个主反馈，现在是 `:active` .98 + 回弹），这是第二个；② 枯草金配额按**同屏同时可见**算、不按寿命算——一次 5 枚就是 5 处，"用完即清"不成立；③ §12 那条禁涟漪的真实理由是"太 Material"，把水换成叶，形状没变。**本站的森林版点击反馈已经有了**：惊起萤火虫（§8.6）——被手惊动的是生命，不是粒子。
- ❌ **把"读过/记得"套上一层假蒸发**（"露水"：读过一篇就在编号右边落一颗点，3 天淡一半、7 天消失）。它不是任何真实事物的记录，是给"我读过"这条事实套了个诗意外壳，还把界面正确性挂在一枚没人能核对的时钟上——§12 禁假数字的近亲是**假语义**。另外两点单独也不成立：3px 的露珠画"边缘一道高光"撞 §0"磨砂不抛光"；编号右边那一格已经被封面的 `.cover` 占了。本机状态要留就用**墨色差**（读过＝那一行深一档），别用会自己消失的东西。
- ❌ **把 404 的地址藏起来让人找**（"迷路的人"：远处微光、光标接近才浮现地址）。详见 §9 那条——列地址是这一页唯一的职责，藏起来等于用可用性买气质；且它对键盘/触屏用户是**页面失效**而不是"降级"。想要"雾更浓"，改 `--band-a` 就够了（现成的乘数，零新元素）。
- ❌ **编一个访问量**：本站是纯静态站点，没有服务端、没有统计脚本，"访客 N 人 / 今日 X 次"这类数字**拿不到**，所以关于页的站点档案里没有这一栏（§15）。唯一允许的"活数字"是 `localStorage` 里本机的载入次数——它真的有来源，且读不到时整行不出现（隐私模式下显示"第 0 次"同样是假数字）。要给全站加真实统计，代价是引入第三方脚本或自建计数器后端，那是另一笔账，别用文案糊过去

- ❌ ⚠️ 把 `--ink-3`（装饰档）或 `--moss-deep`（大字档）用在正文级小字上——见 §2.4
- ❌ **照片透字**（`background-clip:text` 拿首屏那两张照片当 Hero 标题填充）——reactbits 的 MaskedHeading 那一半。四配逐像素实测：α=0 时 ≥7:1 的字形像素 0%–28.5%，连 3:1 的尺寸档都只有 6%–73% 过线；要追平实心 `--ink` 得把 guard 压到 α≥.95，那时纹理已经不存在。数字在 §2.4，**别再提第三轮**。（同一条里"按词错落"那一半没有对比度问题，已落地，见 §8.2）
- ❌ **段落首字先落**（第五轮，动效版）。两个独立理由：① 每滚到新段落就缩一次＝在阅读区里放一个**持续动的东西**，正面撞 §1.2"一处动处处静"；且 0.6s 的缩回是 §1.3 明禁的"1s 以内的活泼动画"。② 换成静态首字放大也不行——那条 32px 苔绿短线**已经是"章"的记号**（§15 详情页），一章里不该出现两种起头记号。想要"段落有重量"，本轮的落点是 §8.7 那条身后的雾：段落**离开**的时候有样子，比进来时抖一下更贴这套排面。
- ❌ **指尖划过苔藓**（第五轮，触屏）。手指划动＝滚动，痕迹会抹在**移动中的内容**上：要么跟着内容一起走（那就是给滚动加一层贴图，掉帧），要么钉在视口上（那就是屏幕脏了）。⚠️ 上一轮"触屏那盏灯**刻意不跟手**"就是为了让开滚动（§8.5），这条会把它请回来。触屏在本站的既有反馈已经有了：按住即亮的灯。
- ❌ **一周后雾带漂移快 15%**（第五轮，"森林认出你"的第一版提案）。65s→55s 是一条极慢漂移上的改动，**读不出来**——那正是"看不见的内部微动"那一类（§9 显示设置钮图标 0.9px 的同族教训），却要为此新增一枚存储键 + 一处 JS 覆写 `animation-duration`。**意图我接，量不接**：要落在读得出的量上，目前没有合格候选，别再提"更小但更勤"的版本。

- ❌ **"记忆的纹理"：随访问次数让纸张/人像颗粒变深**（第五轮，**挂起**而不是否决）。原本三条：① **载体还没有**——人像位当时是空槽（§13）；② "随访问次数增长"是**不可核对的时钟驱动装饰**，§12 那条"露水蒸发"禁的正是这个近亲；③ 它还会让 §2.4 里人像那笔读数漂移。⚠️ **①在同一天下午作废**——头像到位了（§13），所以这一条现在只剩②③撑着，**结论不变但理由变窄了**：撑着它的不再是"没有东西可放"，而是"不许把界面正确性挂在一枚没人能核对的计数上"。**如果将来要做，正确形态是"这一页为你换过一次材质"这种一次性、可核对的差别**（比如本机首次载入 vs 之后），不是持续加深

## 15. 子页面规格（/essays / /essays/<slug> /things /about /notes）

> 2026-09-27 修订：站点拆为多页；同日第二轮由静态多页迁到 Astro，子页面共享底座在 `src/styles/mistwood.css`（+ 各页 `essay.css` / `notes.css` / `home.css`）与 `src/scripts/site.js`（全站交互）、`src/scripts/hero.js`（首页氛围层），公共外壳是 `src/layouts/Layout.astro`。**首页那轮"仍是单文件"的归并重构已随迁移完成**，六页共用同一个 Layout，导航/字体/主题引导只有一份（⚠️ 原先也在这一份里的页脚已于同日撤掉，见 §9）。

- ⚠️ **首页下半段**（第四轮新增，`index.astro` 里 `.home-lower`）：Hero 仍旧整一屏（`min-height:100vh` 一个字没改），下面接**最近三篇的目录行 + 最新一条 note**。这一段的身份是"观察日志那三个数的实例"（§4 / §7），不是第二个 `/essays/`，四条约束：
  - **几何跟 `.hero` 不跟 `.wrap`**：`max-width:1120px + padding:0 8vw`、**不 `margin:auto`**。子页内容居中而首页 Hero 左靠，如果这段用 `.wrap`，1440 宽下标题左缘 115px、行左缘 275px——两不对齐。实测 531×559：`.home-lower` 顶到 `scrollY=559`（正好一屏），`scrollHeight` 从 559 变 1203

  - **条数封顶 3**（`posts.slice(0,3)`）：再多就不是"附录"是"目录"了，而目录已经有它自己的一页
  - **最后一行是 note 不是链接阵列**：`日期 + 一两句话`（§7 notes 的形），整条链到 `/notes/`（真实页面，不破 §12 死锚点），文本走 `inlineMd` —— 与 `/notes/` 上同一份文本同一个解析口径，两处两种渲染迟早分叉。它下面只剩 22vh 留白，"再走回雾里"那一拍由这句话承担（§5）（⚠️ 2026-09-28 §6.4 给它加了重量：**19px 宋体 `--ink`**，原来是 15px 无衬线 `--ink-2`——比上面三行 22px 衬线的目录标题还轻，等于让附录盖过作者；宋体是长文那张脸的字体（§3），声音该用读正文的那副嗓子说。19px 不在 §3 层级里是故意的，和 §3 那条"卡片标题不在这套层级里——它们是石头不是标题"同一个理由。两处连带修的 bug：① 这一格**不再写 `line-height`**——`.home-note p`(0,1,1) 的权重压过 `tone-*`(0,1,0)，上一版的 1.85 让 §15"手记的呼吸"三档**在首页从来没生效**（实测 27.75px 而不是 `tone-breath` 的 29.25px；关于页那两处是好的，因为 `.now-list` 把 line-height 设在容器上由 span 继承）；② 日期那一列从写死的 64px 改成 `max-content`——`2026.09.25` 在 12px 等宽 + .12em 下要 86px，溢出 22px、压到句子左缘 4px，实测修完留白回到干净的 18px)。

- **导航**：与首页同胶囊，当前页链接常亮（`.here` = 文字左侧一枚实心点，⚠️ 不再是下划线，理由见 §9）。⚠️ 六页同 5 项；子页导航入场是 `.3s`（没有 Hero 时间轴要对齐），首页那 `1.4s` 属于 §8.2
- **底色**：`--bg-top` → `--bg-base` 的 40vh 短渐变落地，像从雾里走出来之后站定的地面。⚠️ 2026-09-28 起这条渐变之上还叠**同一盏方向光**（左上、随 `data-phase` 转仰角，机制与数字在 §2.3 末）——子页从此不是"一张没打光的平纸"
- **开场三档 + 一层气**（2026-09-27 第三轮）：原先子页第一屏就是一行标题压在空底上，阅读动线没有"进场"。现在开场由三层叠出来——底（上面那条 40vh 渐变）· 气（`.page-head::before` 一条 `--mist` 横向雾带）· 字（标题与 `.sec-label`）。三档不是一组随机数，口径是**内容越要沉下来，开场越高**：
  - `look`（/things/，看图）桌面 `--head-top:30vh` / 窄屏 24vh · `read`（/essays/ /notes/ /about/，读字）22vh / 18vh · `lost`（404，迷路的人不需要仪式感）14vh / 12vh。`tier` 由 `Layout.astro` 的 prop 写到 `<html data-tier>`，默认 `read`，所以只有 look 与 lost 两页要点名
  - **带子的中心钉在标题行盒上**：`top = --head-top − (--band-h − 1.85×--title-size)/2`，`1.85` 是从 body 继承的行高。实测三档 drift 全 0px——换档、换视口、改标题字号都不用重摆，也不留"魔数往上挪 3vh 看着差不多"那种债
  - ⚠️ **全出血用 `left:50% + width:100vw + translateX(-50%)`，不是两边各留 -8vw**：`.wrap` 有 1120px 上限，宽屏下内容盒离视口边远不止 8vw，负内边距会在左右各留下一道看得见的竖直断边（渐变是竖向的，救不了横向的边）。100vw 比可视区宽出滚动条那几像素由 `body{overflow-x:hidden}` 吃掉——实测 `scrollLeft` 设 200 仍然回到 0
  - ⚠️ **气这一层必须在 `z-index:-1`**：它若排在文本之上，就是给标题蒙了半层白，§2.4 那笔按纯色底算的账当场作废
  - ⚠️ **窄屏的三档必须在媒体查询里用同名选择器各压一档**：`html[data-tier] .page-head` 权重高于裸 `.page-head`，只改后者的话 look/lost 两档会悄悄留在桌面高度上
  - **零新增循环**：这一层是静态渐变，没有 `animation`、没有 `filter`（§1.4 的三种模糊一个都没多）、不占 §1 的常驻预算——子页面那条"只剩颗粒 + 至多一个呼吸点"的账原样成立
  - ⚠️ **主题切换那一下它是瞬间换色的，已知且明知故犯**：`--mist` 是自定义属性，换主题时梯度整体重算，而 `background-image` 不在 §8.8 的白名单里，也不在"颜色与不透明度过渡保留 200ms"那份例外名单里，所以不能顺手加 `.8s` 过渡。量过它到底跳多少：亮色带心把底提亮约 8 个 sRGB 单位（`#EDE9DD` → `#F4F1EA`），夜林是 9 个（`#12170F` → `#1B2119`），而身下那张底正在 `.8s` 里慢慢走——跳的是那 8–9 单位、且立刻被底下的淡化吃掉。真要抹平，办法是把亮暗两条带子叠起来用 `opacity` 交叉淡化（§5 照片那一招），为一点氛围多养一个元素不值
  - `prefers-reduced-transparency:reduce` 下整条撤掉（`display:none`）：氛围没有"退回实面"的解法，实面就是一块白板；它是绝对定位的，撤掉不改一行版面、不改一次换行
- **内容数据化**：列表型内容两处——文章是 content collection（`src/content/posts/*.md`，front matter 认 `title` / `date` / `excerpt` / `cover` 四个键，⚠️ 第五轮起多一个**可选第五键 `hour`**（0–23，见 §7），键由 `src/content.config.ts` 的 zod schema 钉死），小东西与碎碎念在 `src/data/site.js`。**没有第二份清单**：旧版 `assets/content.js` 那种"md 文件和清单各写一遍"的结构已废除，改一边忘另一边的失真从原理上消失；页面数字在构建期取集合长度，运行时不请求任何数据
- **文章正文**：`src/content/posts/<slug>.md`，构建期由 `src/lib/markdown.js` 渲染进 `/essays/<slug>/`（解析器是从旧版逐行搬来的，没有换引擎）。⚠️ 排版白名单**这轮从 6 项扩到 12 项**：段落 / `##` H2 / **`###` H3** / `*斜体*` / `` `code` `` / `[文字](链接)` / `![alt](src "可选图注")` / **`-` 与 `1.` 列表 / `>` 引用（末行 `—— 署名` 变 `<footer>`）/ `---` 分隔线 / `[^id]` 脚注 / `^[文字]` 边注**，除此之外仍不存在（=排版元素不会超纲）。⚠️ 原先只有六项是子页单调的直接原因：文章排不出结构，装饰救不回来。写死的规矩：
  - **图片只有块级**。独占一行的 `![alt](src "图注")` 渲染成图版（`.frame` 圆角 16 + 下方 12px 等宽图注）；写在句子中间的图会被**提到段后**落图版——680 栏里没有"行内缩略图"这种位置，别去救它。整段是 `[![图](src)](链接)` 时图版整体可点。
  - **列表不嵌套**，整块每一行都得是项才算列表；接受 `-` 与 `*` 两种项目符、`1.` 与 `1)` 两种编号（⚠️ 这是白名单的**实测超集**，写文档时别当成只有 `-`/`1.`）。有序列表**沿用作者写的起始号**（`3.` 开头渲染成 `<ol start="3">`）。
  - **脚注**：`[^id]` 在正文里编号，**编号按"第一次被引用"排，不按定义顺序**（定义习惯写在文末，引用却在开头，一趟扫下来会把第一处当成缺号——所以渲染器是两趟）。同一处被引用两次时号数复用，但 `id="fnref-*"` 只给第一次，否则锚点重复。文末列表每条尾带 `↩` 回链 + `aria-label`，跳到落点靠 `:target` 点亮，零 JS。⚠️ **引用了却没定义 ⇒ 渲染成一个不带号、不带链接的 `∗`**——绝不给死锚点（§12）；定义了却没被引用 ⇒ 不进文末列表。这两种都是"作者写了但读者看不见"，由 **`npm run check` 里的 `new-post.mjs --check` 扫真实文章**拦下（`check-markdown.mjs` 只钉渲染器行为，它不读 posts/，别指望它查稿子）。
  - **脚注 id 会先归一化再进 `href` 与 `id`**：只留 Unicode 字母/数字/连字符，其余换成 `-`，首尾去干净，限长 32。⚠️ 归一化不是洁癖——原先按 ASCII 白名单清，`[^注一]` 和 `[^注二]` 都会塌成空串，两条注合并成一条、锚点还会撞车。两个 id 撞成同一个键时 `--check` 直接报错。
  - **`code` 里的东西一律按字面出现**：反引号段最先被摘出来占位，所以 `` `[^1]` ``、`` `^[x](url)` ``、`` `[文字](链接)` `` 都不会被当成排版件。⚠️ 这条是后补的——原先 code 的替换排在最前但只包了 `<code>` 壳，后面的规则照样往里钻。
  - **边注** `^[文字]`：一个元素两种落位、内容只有一份——≥1240px 浮进正文左缘的边注栏，窄屏就地留在句间并用全角括号 `（¹……）` 与正文隔开。**不许用 `display:none` 藏边注**，那是把作者写过的话删掉。⚠️ 脚注与边注这套语法**只在整篇渲染里生效**（`renderMd` 打开 `allowRefs`）；notes 那种单段调 `inlineMd` 的场合保持字面，免得在别的页面上长出没人认领的注号。

## 16. 日常写作与构建

> 这一节不管视觉，只管"新增一篇文章要敲哪几条命令"。规范其余章节约束的是**写出来的东西长什么样**，与此处互不覆盖。

- **写一篇新的**：`npm run new-post <slug> "标题" [--date 2026.09.27] [--excerpt "一句话摘要"]`
  - slug 只允许小写字母 / 数字 / 连字符（它直接进 URL），日期要 `YYYY.MM.DD`，同名文件**不覆盖**
  - 列表页现在只有一种形状（目录行，§15）：`excerpt` 写不写都在那里——写了它就在悬停时显形，没写就不占位。**不再有"B 卡 / C 卡"两种模板**，`cover` 也一样：填了就挂一枚 92px 缩略图，没填就没有那个盒子
  - 骨架里那行示例图是**哑的**（括号里带空格），删掉空格才变成真图；这样图还没到位时 build 不会红
- **正文能用的排版件**（本轮从 6 项扩到 12 项，语义与限制见 §15）：`### 小节` · `- 项目` / `1. 编号` · `> 引用`（末行 `—— 署名`）· `---` 分隔线 · `[^id]` 脚注（定义写在文末，一行一条，续行接上一条）· `^[文字]` 边注（宽屏浮到左缘，窄屏就地留在句间，**不会消失**）
- **发布前**：`npm run gate` —— 2026-09-28 起门禁分两层，`gate` = `npm run check && npm run build && node tools/runtime-check.mjs`；只想跑源码级那三类就 `npm run check`。⚠️ 第四类（运行时 DOM）**不能**塞进 `check`：`check` 三项都不读 `dist/`、而且在 build 之前跑，干净检出上 `npm run check` 会因为"没有产物"直接红——分层理由是依赖方向，不是口味。`check` 一条命令查三类事：① `new-post.mjs --check` 扫**真实稿件**——front matter 合不合 schema、有没有会炸 build 的相对图片路径、**脚注引用与定义配不配对、两个脚注 id 会不会归一化成同一个锚点**；② `check-markdown.mjs` 扫**渲染器本身**的回归（图版/链接/白名单/属性注入，这轮另加列表、引用、分隔线、h3、幽灵引用不造死锚点、中文 id 不塌、`code` 里的语法按字面、句中连字符不会被误认成署名、`^[注](url)` 不变链接），三轮 fixture；③ `palette-check.mjs` 扫**色板**——按 §2.4 的 L 档位算对比度，压线就红。⚠️ 第五轮起它做三件事、这一轮到四件：**基准**（从两份表读 hex 令牌，对 `--bg-base` 与 `--bg-top` 各算一次）、**双表漂移**（`mistwood.css` vs `home.css` 同一选择器下同名令牌逐字符比对，22 枚 hex + 16 枚含 `rgba()` 的面/影/纱，谁分叉直接红——这条是 §16 那条"home.css 重复"债的第一道自动闸门）、**条件块**（把 `html[data-phase=…]` / `[data-moon=…]` 按档合并进基准再复算，dawn/dusk/night × 满月共六档，口径与实测数字见 §2.4）、⚠️ **方向光**（2026-09-28 第四件事：把 `--lit` 当"铺满全页"合成进有效底顶再复算一遍地板，跑 12 档；`--lit` 缺失或 α=0 直接红——判据不许空转。机制与两次变异测试见 §2.3 末）。⚠️ 分工要看清：稿件内容的问题只有 ① 拦得住，① 不读渲染器；改渲染器不会让 ① 变严；③ 认的是**十六进制字面量**与**值里含 `rgb()/rgba()` 的令牌**，写成 `hsl()`、颜色字面名（`red`）、或搬到组件里写死的色它仍然看不见。⚠️ **新加判据必须做一次变异测试**：③ 的漂移检查第一版要求"值以 `rgba(` 开头"，于是 `--shadow:0 12px 24px -8px rgba(…)` 这种一长串偏移打头的写法一个字都不中，**检查静默空转、退出码 0，长得像全绿**；故意把 `home.css` 的傍晚 `--shadow` 改一位小数它仍然 exit 0，这才被发现。修好后同一处改动 exit 1、还原后 exit 0——**"扫了但没匹配到"和"扫了且全过"在两串输出里是同一种样子**，只有故意弄坏一次能分开它们（⚠️ 2026-09-28 的第四类 `runtime-check` 同规矩，它自己的五格变异测试记在下面那条）。四类分工现在是：**①稿件 ②渲染器 ③色板 都在源码上、`check` 里；④运行时 DOM 在产物上、只在 `gate` 里**——④抓的正是前三类原理上抓不到的那一族："语法完全合法但整段不执行"

  - ⚠️ **每页跑两档，这是本卡最贵的一条**：只跑"资源齐全的完整档"是**假门禁**——`site.js:37` 把 dataset 当唯一真相源读回来，第 40-43 行 `paintSettings()` 又原样写回 `root.dataset`，所以**内联脚本整段不跑时 `data-fog/data-grain/data-fireflies/data-enter` 照样是 `normal/on/on/auto`，五枚一枚都不少**（变异测试第一次就这么漏的：改坏 `Layout.astro` 之后完整档 9 份全绿、只有隔离档报红）。于是先整批跑**内联隔离档**（服务端对所有 `.js` 回 404 ⇒ 五枚属性只剩 `<script is:inline>` 一个写者），再整批跑完整档；分两批是为了不让"拦 .js"这个服务端全局开关在两档之间串台。两档各带见证物：隔离档的 `#clock` 必须仍是 `--:--`（否则 .js 根本没拦住，这档白跑），完整档的 `#clock` 必须已被写成 `HH:MM`（否则 site.js 没跑，这档就和隔离档没区别）。⚠️ 见证物**不能**用"radio 上有没有 `checked`"——`i.checked = true` 改的是 IDL property、不回写内容属性，`outerHTML` 里永远 0 枚（实测：模块脚本明明跑了，时钟已变成 `09:24`，`checked` 仍是 0）。
  - **防空转按上面那条老判据做**（"扫了但没匹配到"和"扫了且全过"在两串输出里是同一种样子）：没有 dist / dist 里没 HTML / 找不到 msedge / 临时 profile 建不出来或不可写 / 服务 `EADDRINUSE` / Node 自己都连不上 / dump 为空 / dump 里没有 `<html` / 断言份数为 0 —— 一律 exit 1 并点名是哪一步死的；每页**打印实际读到的属性清单**（缺的显示 `∅`）。⚠️ 另一条踩坑钉在这里：**浏览器必须异步起**——第一版用 `spawnSync`，而 HTTP 服务在同一进程里，`spawnSync` 冻住事件循环 ⇒ 浏览器对 `/` 的第一个请求永远得不到响应 ⇒ 90s 超时，报出来像"浏览器坏了"，其实是自己把服务憋死。
  - ⚠️ **故意没做的三条（不是漏了，是给了不出真判据就别写）**：① `data-revisit`——它只在 `sessionStorage` 已有 `mistwood-seen` 时才写（`Layout.astro:64`），而 sessionStorage 是标签页级的 ⇒ 要同一浏览器**进程内两次导航**，`--dump-dom` 只有一次导航，给不出真判据，脚本里只打印不判定；② 暗色下 `meta[name="theme-color"]` 被改成 `#0E130D`——受上面②约束（这版 Edge 不认 `--force-prefers-color-scheme`），暗色得让 profile 预置 `localStorage.mistwood-theme=dark`，上一轮的做法是往 `dist/` 写一枚一次性种子页，而**门禁不该往构建产物里写文件**（那会让 `dist/` 的内容取决于门禁跑没跑过）⇒ 先不进自动化；③ `SITE` 占位域名做成**默认警告 + exit 0**，只有传 `--strict-site` 才红——现在恒红会让这枚门禁一进门就挡掉所有工作，而逼人绕过门禁比没有门禁更糟。另注：`data-theme` 是这五枚里唯一**弱**的判据，静态产物 `<html lang data-theme="light">` 本身就带着它，所以第一段 IIFE 是否执行并没被这枚证明（第一段唯一独占的效果就是②那枚暗色 `theme-color`）；承担本卡判定的是后四枚。
