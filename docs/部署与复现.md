这份文件管**怎么把这枚站送上线、以及一台新机器怎么复现**。它不管长什么样——那是 `docs/设计规范.md` 的职责，两者冲突时以规范为准，本文件只登记操作事实、现值与故障签名。

⛔ **2026-10-01 11:0x：Vercel 那枚项目已删，上面那一句从今天起不再成立。** 作者的原话是「把 vercel 删了」，我先提了存档、他说「不要存档」，所以是一枚没有备份的 `DELETE`（回执 **HTTP 204**）。⇒ **从今天起：推 `main` 只是同步仓库，不触发任何构建**；本站又回到"唯一的门禁在本地、上线只有 Pages 直传一条路"。全过程与"为什么这台机器无法独立复验删除"在第 ⑮ 格。⚠️ 连带一枚后果：**`~/.config/vercel-tok` 随项目一起失效**（删后所有 Vercel 接口连 `/v2/user` 都回 `forbidden / Not authorized`）——文件我没动、也没删，它现在是一枚死凭证。

⚠️ **2026-09-30 起这一句只管 Vercel 那一侧**。同一天加了第二条上线路径：**本地构建＋直传 Cloudflare Pages**（作者拍的「走 B」，全节在 §3.13）。它的形状和上面那句正好相反——**平台不跑构建**（`clone_repo`／`build` 两枚 stage 恒 `idle`），所以 `PUBLIC_SITE` 那类"忘了填环境变量"的失败在 Pages 侧**没有构建期守卫会拦**，唯一那道闸是本机跑 `node tools/runtime-check.mjs --strict-site`；反过来，Pages 那枚地址**这台机器直连就能打开**（`*.vercel.app` 被 SNI 重置，§3.1），§3.4 的线上清单因此第一次打得钩。

## 1. 一次改动的完整流水线

```
规范先行  →  一张卡一枚 worktree  →  门禁真跑  →  合并  →  推送（＝同步仓库，2026-10-01 起不再触发构建）
                                                    └→ 上线只有一条路：带 PUBLIC_SITE 本地构建 → 数绝对地址 → runtime-check --strict-site → wrangler 直传 Pages
```

1. **规范先行**。先在 `docs/设计规范.md` 里把效果写成"现值＋现在时"的一格，再动代码。规范是权威文件，代码是盘上事实——**对账时读代码，不读规范**（§4 那两行曾写着"区块间距 120–160px""圆角卡片 20"，而盘上最大块间距是 96px、`border-radius:20px` 出现 0 次；2026-09-28 已按现值改写）。
2. **一张卡＝一枚 worktree**。`git worktree add D:/wt/<名> -b card/<名> main`，再把 `node_modules` 拷进去（147 MB；`robocopy` 要 `MSYS_NO_PATHCONV=1`）。数成果**只数分支 ref，永远别读它的 HEAD**。
3. **门禁**见第 4 节。新判据必配两侧变异＋防空转（表空即红、needle 必命中、幻影即红）。
4. **合并**。FF-only（本仓不许合并提交）。子代理被掐断时先读盘上形态：实现体在盘上就原样钉成一枚 `wip` 提交再 rebase，**不重派**（重派撞的是契约不是文件）；盘上零痕迹才重派。
5. **推送＝同步仓库**（2026-10-01 起）。⚠️ 这一句**在 09-29 到 09-30 那天夜里不是这个意思**——那段时间 Vercel 接通了 git 集成，推 `main` 会自动起生产构建（实测三次的账在 §3.9–§3.11）。**那枚项目已经删了**（第 ⑮ 格），所以从今天起"我先推上去再说"重新变回"我只是同步了一下仓库"，**上线必须显式走第 6 步**。
6. **部署**。见第 3 节——**现在只剩一条路：本机带 `PUBLIC_SITE` 构建 → 数绝对地址 → `runtime-check --strict-site` 绿 → `wrangler pages deploy` 直传 Pages**（§3.13 第 ⑥ 格钉死的那条顺序）。⚠️ 平台侧不跑构建、也不跑我们的门禁，所以**本地那三层尺子是唯一挡在发布前面的东西**；也正因为如此，"忘了带 env 就直传"这一族失败从此**没有任何自动拦截**，全靠那条顺序里第 ②③④ 步自己数。

## 2. 推送：这台机器只能走 API

**git 传输层在这台机器上彻底不通**，唯一出口是 `api.github.com`：

```
node tools/gh-push.mjs Alyssumira/Alyssumira-Blog --branch main
```

- **判推送成没成只看 tree sha，不看 commit sha。** 线性化会让每一枚提交的 sha 都漂（2026-09-28 那一次：16 枚提交 sha 全变，而 `tree 8802727` 与本地逐位一致、远端 47 枚文件复验不符 0 多出 0）。拿 sha 对账会得出"推失败了"的假结论。
- **推送会跑过十分钟，别挂前台。** 第十五轮那一次（2026-09-29）实测：本地 243 枚提交里待推 **81 枚**、需上传 **135 个 blob / 26.59 MB**（已去重）、写请求约 **298 次**——前台命令超时转后台才跑完。先 `--dry-run` 读一遍它给的数（它会顺手打"按树认亲"的结果：那次远端头 `109efad` 的树 ＝ 本地 `7259ad1` 的树 `4845214` ⇒ 续推而不改写已发布历史）。推完的核对：远端 `refs/heads/main` 指到 `ccabc13`，而 `git/commits/ccabc13` 的 `tree.sha = 65565f7f…` ＝ 本地 `git rev-parse "HEAD^{tree}"` ⇒ 内容一致。⚠️ 核对时那条 API 返回要落到 `%LOCALAPPDATA%/Temp/` 再读——**node 眼里的 `/tmp/` 不是 Git Bash 的 `/tmp/`**（它解析成 `D:\tmp\`，会报 ENOENT）。
- token 在 `~/.config/gh-tok`。**推完别删**——删了下次要作者重新找。绝不写进 `.git/config`，绝不打印出来。
- 仓库是 `private=true`、`default_branch=main`、约 10.4 MB。fine-grained PAT **不能建仓、不能改默认分支**（实测过），但只推内容够用。

### 3.2 构建形状

纯静态：`npm run build`（= `astro build`）→ 产物 `dist/`。无 adapter、无 SSR、无 API 路由。

- Framework Preset：Astro（自动识别）
- Build Command：`npm run build`
- Output Directory：`dist`
- **Node 必须 ≥ 22.12**。这不是建议是硬性下限：`node_modules/astro/package.json` 的 `engines` 实测是 `{"node":">=22.12.0","npm":">=9.6.5"}`（astro 7.3.5）。Vercel 上选 22 可以，选 18/20 会在 install 或 build 阶段就崩；这台开发机是 24，满足。
- Install Command 用 `npm ci`：`package-lock.json` 确实在库里（实测存在），走它是为了可复现。

⚠️ **`gate` 里的 `runtime-check` 上不了 Vercel**：它要起本机 headless Edge 读 `dist/` 的运行时 DOM（`package.json:14 的 gate 那一行`）。所以 Vercel 侧 build command **只能留在 `npm run build`**，"没填真域名不许上线"那枚牙必须落在构建入口 `astro.config.mjs` 里，不能指望门禁——这是本站守卫写在 config 而不是 tool 里的原因。

### 3.7 搜索索引：`dist/search.json` 在哪一步生成、换域名跟不跟、失败长什么样（2026-09-29 `card/search` 新增）

- **哪一步生成**：`npm run build`（`astro build`）期间由 `src/pages/search.json.js` 作为一条静态路由产出——build 日志里那一行 `/search.json (+5ms)` 就是它，落点 `dist/search.json`。今天实测 **13,196B / 3 篇文档**（源码 3 篇 · 可见 3 篇 · 草稿 0 篇）。它**不在 `public/`、不需要独立脚本、服务端零依赖**：与 `rss.xml` / `atom.xml` / `sitemap-index.xml` 同一族，托管只要静态文件就够（Vercel 那一格不用加任何东西）。
- **里面装什么**：`{ v: <索引版本号>, docs: [{ u, t, e, b }…] }`——`u` 站内相对地址 `/essays/<slug>/`、`t` 标题、`e` 摘要、`b` 正文纯文本；中文切词按**二字滑窗（bigram）**，切词与命中的口径住在 `src/lib/search.js`，构建期 / 运行时 / 门禁跑的是**同一份**（不是一处真值写两遍）。
- **换真域名它跟着变吗：不变，一个字节都不用改。** 它不读 `SITE` / `PUBLIC_SITE`，产物里的 `u` 全是站内相对地址（`tools/search-check.mjs` 第 ① 格判的就是"一个绝对地址都没有"）；运行时 fetch 的也只是 `'/search.json'` 这枚相对路径。换域真正要动的是那些**绝对地址**——`PUBLIC_SITE` 一枚消费者清单见 §3.3（八处、产物里 200 处），操作流程在 §3.8；`search.json` 不在那张名单上。⚠️ 唯一会动它的是那枚 `v`：**改了切词法或字段就得同时改 `INDEX_VERSION` 并重发**——只重发不改 `v`，CDN 上那份旧索引会被运行时按形状判成"没取到"（见下面最后一条），那只比 404 更难查。
- **失败长什么样（症状 → 根因，都是量过的）**：
  - 没 build 就 `npm run check` → 第 ⑦ 项红（⚠️ **那一枚 ⑦ 是第十一轮 `card/search` 当年挂在 `check` 末项的 `search-check`**，合并时按它自己那条"分层理由是依赖方向"挪到了 build 之后；今天 `check` 的第 ⑦ 项是本轮的 `media-check`，它只读源码、没 build 也**不会**红——别把两个 ⑦ 读成同一枚）：`dist/search.json 不在 ⇒ 端点没产出（没跑过 build、build 半路炸、路由改动、当成 dev-only 都长这样）`、exit 1。⚠️ 这一项是链上**第一个**读 `dist/` 的（§16 那句"`check` 每一项都不读产物"已随之作废），所以 `check` 必须在 build 之后跑才看得见它的全貌——没产物时它是**红**，不是被 `if` 跳过装绿（文件头那枚总闸：一条断言都没跑过＝红并打印"判据正在空转"）。
  - 产物里冒出绝对地址（有人拿 `SITE` 去拼 `u`）→ ① 红。
  - 草稿泄漏 / 索引篇数 ⇄ 源码可见篇数不等（谁绕过 `visiblePosts()` 直接 `getCollection('posts')`）→ ② 红并点名是哪一篇；同一件事链上第 ⑥ 项 `taxonomy-check` 与 `runtime-check` 的草稿那格也会红（三侧同抓，不是只有产物侧）。实测过两侧：临时给 `fog-debugging.md` 标 `draft: true` ⇒ 索引掉到 **2 篇**、`dist/essays/index.html` 里 0 提及、② 打"源码里草稿 1 篇（fog-debugging）逐个确认不在索引里"；`git checkout --` 还原后重跑 build ⇒ 回到 **3 篇**（本轮逐字量过）。
  - 检索其实没吃正文（只喂了标题摘要，或正文被截断）→ ④ 那张三索引对照表红：full 那枚必须非零、另两张必须为零，多篇窗期望 3 篇。
  - 访客那一侧 fetch 失败（404／CDN 把 `.json` 换成首页 HTML／形状不对）→ **不假装零命中**：说明行回那句实话 `索引没取到，这一格现在搜不了。刷新一次试试。`，同时把在途的 promise 清空 ⇒ 下一次输入会重发（不清就是"搜索框永远搜不到东西、看起来只是没结果"那一档）。`v` 或 `docs` 对不上走的也是这一句——**"形状不对就算红，不算零条"**，与 `没有一篇里出现过「…」` 那句分成两句是有意的。
  - 换域名之后 `/search.json` 404：先查托管有没有把未知路径回成首页（SPA rewrite 一开，`fetch` 拿到的是 HTML、`r.json()` 当场 reject ⇒ 走上面那句实话，页面看起来"搜索坏了但没报错"）。站内相对地址这一条帮不上这个忙，它只保证**不需要改**。

### 3.8 换域名：三步、两枚别动、回退一条（2026-09-29 作者定的落点）

**决策**：目标域名用 **Open Domains**（`open-domains.com`——发的是别人后缀下面的一枚名字，自带 managed DNS；提交要走**人工审核**，2026-09-29 此刻还没批）。批之前先用 Vercel 给的 `*.vercel.app` 上线一次。**这一步的价值不在地址好不好看，而在把 §3.5 那四项"未验到"变成实测**——那四项跟用哪枚域名无关。⚠️ 代价点名：vercel.app 这枚地址**在这台机器上打不开**（§3.1 那三格：通配式污染＋SNI 重置），所以这一次上线的验收窗口不在浏览器里，在下面第 4 条。

⚠️ **本节那三步的"平台"那一半已经被 §3.13 改写了形状**（2026-09-30）：三步里前两步（去平台加那枚地址、读它显示的那条记录）**照旧成立**——Pages 也要在项目上加自定义域名；但后两步（改 `PUBLIC_SITE` → **手动 Redeploy**）在 Pages 侧变成**「带新 env 本机重构建 → 直传一次」**，因为直传不吃平台构建、也没有"改了 env 不重建"这个坑（`env_vars` 恒空）。上面那句"验收窗口不在浏览器里"**今天不再是代价**：Pages 那枚 `*.pages.dev` 在这台机器上直接打得开（§3.13 第 ④ 格）。⚠️ 但**给 Pages 加自定义域名那一步本轮没走、也没测**（域名未批），`POST /accounts/{A}/pages/projects/{name}/domains` 的字段与证书签发方式**未验到**，别照 Vercel 那套推。

**三步**

1. **Vercel 加域名，照它当时显示的那条记录填**。Settings → Domains → Add → 填全名。⚠️ 它要的不一定是 CNAME：如果那枚后缀在 Public Suffix List 上（免费子域名服务常在，为的就是给每个用户隔离 cookie），Vercel 会把 `名字.后缀` 当成 **apex** 处理，向你要 **A 记录**。Open Domains 面板 A／CNAME／TXT 三样都有（A 与"NS 要 £2+"那两条是 2026-09-29 那张面板截图上直接读到的，CNAME＋TXT 是作者在 Type 下拉里读到后转述给我的——两档来源不同，记清楚），两条路都走得通，**但记录与值以 Vercel 那一页显示为准**：CNAME 每项目独有（形如 `xxxx.vercel-dns-017.com`，文档里那枚是样例，抄不得）。⚠️ 那枚 **NS 要 £2+ 捐款**的档位本站**用不上**，别为它掏钱：NS 委托只为通配符 `*.域名` 的证书签发服务，单枚具体名字的证书走 HTTP 验证。撞"域名已被别的 Vercel 账号使用"就按它给的 token 加 TXT。
2. **改 `PUBLIC_SITE` 的 Production 值，然后手动 Redeploy**。⚠️ 最容易漏的就是这一格：Vercel 不会因为环境变量变了就重建，而 Astro 的 `site` 是**构建期**烘进产物的 ⇒ 不重部署，线上那 **200 处**绝对地址仍是旧域名，页面看着完全正常，只有去读 `/rss.xml` 才发现没换过来（处数与逐文件账见 §3.3 那张表）。只给 **Production** 那一档；给预览档会把 `*-git-main-*.vercel.app` 写进 `canonical` 与 `og:url`。
3. **核线上，不是核 `dist/`**。`runtime-check` 的普查窗口是本地产物，它证不了线上。抓 `/rss.xml`、`/atom.xml`、`/robots.txt` 的 `Sitemap:` 行、`/sitemap-index.xml`、`/sitemap-0.xml`、`/llms.txt`，加任意一页的 `<link rel="canonical">`／`og:url`／`og:image`／JSON-LD：新域名该在的地方全在、旧域名残留 **0 处**。
4. **验收窗口**（这台机器的现实）：浏览器打不开 vercel.app ⇒ 三条替代路各有代价。① `api.vercel.com` 已实测可达（403＝没带凭证，TLS 是过的）⇒ deployment 的 ready 状态、构建日志、域名配置都能读，**能证"构建真成功、产物是纯静态、绝对地址是真域名"，证不了"浏览器里渲染正常"**；要用它得在 Vercel 建一枚 API token，放 `~/.config/vercel-tok`（与 `gh-tok` 同档：不进仓库、不打印、推完不删）。② 换出口：手机热点把那枚地址打开，肉眼过双主题 × 四时段——这条最接近访客真实体验。③ 本机 `astro preview` 跑像素：不需要线上域名，但也就不验"线上"那一层。⚠️ 我不会去动本机的代理开关（`127.0.0.1:7890` 那枚）来绕这条 SNI 规则，那是你的机器设置。

**两枚别动**

- **别删 `*.vercel.app` 那枚**。换完两枚 host 同时服务同一个项目 ⇒ 存过旧链接的人照样打得开，这是免费的保险。反面照实说：同一份内容有两个 origin，`canonical` 只写一枚；本站没有 SEO 诉求，**不为这件事加机制**（真要收是 Vercel 侧一条 redirect，不是代码）。
- **别改 project slug**。删掉 vercel.app 那枚、或者改了项目名，旧地址才是真断。改 slug 之后 Vercel 会不会给旧 slug 留跳转——**未验到**，别赌。

**回退只有一条**：发放方哪天收回那枚名字 ⇒ `PUBLIC_SITE` 改回 `*.vercel.app` ＋ 一次 Redeploy。这就是"先有一枚不依赖任何人批准的落点"的意义。

**新域名到手，第一件事是跑这三枚测试**（顺序照 §3.1）：系统解析器看它回什么 IP → `--resolve` 钉 Vercel 真 IP 看还重不重置 → 浏览器／无头 Edge 真打开一次。自定义域名的 SNI 里没有 `.vercel.app` 那串，**很可能**绕开今天拦我们的这条规则——但那是推断，测过才算数。

**这一节的未验到**（第一次真换时回来打钩）：✅ **① 已结（2026-10-01）**：发放方后缀 `living-the.life` **不在 PSL**（`public_suffix_list.dat` 334,786B 里命中 0 次，只有 `life` 那枚 TLD）⇒ 走 CNAME、不要 A 记录；⚠️ 但这一节的**主体流程整条作废**——本站没走 Vercel 加域名那一步，走的是 **Cloudflare Pages**，操作账在 §3.13 第 ⑭ 格（那里也记了"回执不告诉你该填哪枚值"这一格未验到）。② Open Domains 的条款／收回政策／有效期——它的公开页在 Cloudflare 挑战后面，我这窗口读不到，只有面板上那几行（CNAME＋TXT 有、NS 要 £2+、`Reviewed before activation`）算实测；③ 改 slug 后旧 vercel.app 地址是否跳转；④ 免费子域名会不会撞 Vercel 的反滥用判定（同后缀下大量域名共享出口那一类）——我没读到过它的原文，所以标"未验到"，不是"不会"。
