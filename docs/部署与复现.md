# 部署与复现

这份文件管**怎么把这枚站送上线、以及一台新机器怎么复现**。它不管长什么样——那是 `docs/设计规范.md` 的职责，两者冲突时以规范为准，本文件只登记操作事实、现值与故障签名。

⚠️ 写这份文件的原因是：本站**今天还没有任何 CI/CD**。`.github/workflows` 不存在，推完 GitHub 只是仓库更新，线上没有东西在跑。第 3 节描述的是"接上 Vercel"这条路，接上之前它都是待办。

---

## 1. 一次改动的完整流水线

```
规范先行  →  一张卡一枚 worktree  →  门禁真跑  →  合并  →  推送  →  （待接）部署
```

1. **规范先行**。先在 `docs/设计规范.md` 里把效果写成"现值＋现在时"的一格，再动代码。规范是权威文件，代码是盘上事实——**对账时读代码，不读规范**（§4 那两行曾写着"区块间距 120–160px""圆角卡片 20"，而盘上最大块间距是 96px、`border-radius:20px` 出现 0 次；2026-09-28 已按现值改写）。
2. **一张卡＝一枚 worktree**。`git worktree add D:/wt/<名> -b card/<名> main`，再把 `node_modules` 拷进去（147 MB；`robocopy` 要 `MSYS_NO_PATHCONV=1`）。数成果**只数分支 ref，永远别读它的 HEAD**。
3. **门禁**见第 4 节。新判据必配两侧变异＋防空转（表空即红、needle 必命中、幻影即红）。
4. **合并**。FF-only（本仓不许合并提交）。子代理被掐断时先读盘上形态：实现体在盘上就原样钉成一枚 `wip` 提交再 rebase，**不重派**（重派撞的是契约不是文件）；盘上零痕迹才重派。
5. **推送**。见第 2 节。
6. **部署**。见第 3 节，目前未接。

## 2. 推送：这台机器只能走 API

**git 传输层在这台机器上彻底不通**，唯一出口是 `api.github.com`：

```
node tools/gh-push.mjs Alyssumira/Alyssumira-Blog --branch main
```

- **判推送成没成只看 tree sha，不看 commit sha。** 线性化会让每一枚提交的 sha 都漂（2026-09-28 那一次：16 枚提交 sha 全变，而 `tree 8802727` 与本地逐位一致、远端 47 枚文件复验不符 0 多出 0）。拿 sha 对账会得出"推失败了"的假结论。
- token 在 `~/.config/gh-tok`。**推完别删**——删了下次要作者重新找。绝不写进 `.git/config`，绝不打印出来。
- 仓库是 `private=true`、`default_branch=main`、约 10.4 MB。fine-grained PAT **不能建仓、不能改默认分支**（实测过），但只推内容够用。

## 3. 生产部署（Vercel）——待接，先把事实钉在这里

### 3.1 这台机器的可达性（2026-09-29 实测）

| 端点 | 读数 | 含义 |
|---|---|---|
| `https://api.vercel.com/v6/user` | **403** | TLS 与网络都通，只是没带凭证 ⇒ Vercel 这条路可走 |
| `https://vercel.com/new` | 200 | 控制台可达（但浏览器侧授权得作者自己做） |
| `https://api.netlify.com/api/v1/user` | 000 超时 | **Netlify 今天走不通** |
| `https://fonts.googleapis.com` | `SEC_E_UNTRUSTED_ROOT` | 被校园 Scholar CA 中间人；DoH 拿到的答案也是脏的（`223.5.5.5` 回 `220.181.174.33`，不是 Google 地址段） |
| `https://fonts.loli.net` | 200 | 本站产物真正用的那枚镜像可达 |

Vercel 的构建是它自己服务器端去 GitHub 拉，**与这台机器的 git 传输层无关**——所以第 2 节那套 API 推送限制不影响 Vercel 走 Git 集成。

### 3.2 构建形状

纯静态：`npm run build`（= `astro build`）→ 产物 `dist/`。无 adapter、无 SSR、无 API 路由。

- Framework Preset：Astro（自动识别）
- Build Command：`npm run build`
- Output Directory：`dist`
- **Node 必须 ≥ 22.12**。这不是建议是硬性下限：`node_modules/astro/package.json` 的 `engines` 实测是 `{"node":">=22.12.0","npm":">=9.6.5"}`（astro 7.3.5）。Vercel 上选 22 可以，选 18/20 会在 install 或 build 阶段就崩；这台开发机是 24，满足。
- Install Command 用 `npm ci`：`package-lock.json` 确实在库里（实测存在），走它是为了可复现。

⚠️ **`gate` 里的 `runtime-check` 上不了 Vercel**：它要起本机 headless Edge 读 `dist/` 的运行时 DOM（`package.json:13`）。所以 Vercel 侧 build command **只能留在 `npm run build`**，"没填真域名不许上线"那枚牙必须落在构建入口 `astro.config.mjs` 里，不能指望门禁——这是本站守卫写在 config 而不是 tool 里的原因。

### 3.3 上线前必须落的两枚 env

| 字段 | 默认值（不设 env 时） | 出处 | 下游 |
|---|---|---|---|
| `PUBLIC_SITE` | `https://mistwood.example.com` | `astro.config.mjs:6` | canonical、`og:url`、`src/pages/rss.xml.js:9`（`site: context.site`）、`sitemap`；产物里占位域名 43 处 |
| `FONT_HOST` | `https://fonts.loli.net` | `src/data/site.js:4` | `Layout.astro:18` 拼 `css2` 请求、`:47` preconnect；字体文件域名由它**派生**（映射表在同文件，`fonts.loli.net → gstatic.loli.net`、`fonts.googleapis.com → fonts.gstatic.com`） |

两枚都是"默认值＝今天的行为"，所以不设 env 的构建产物必须与改动前**逐字节相同**（这张卡验收就这么定）。取舍：`loli.net` 是为校园网选的镜像，海外访客可能更慢——**这是受众判断，归作者**，改的只是开关存在与否。

### 3.4 上线那一次的验收清单

```
npm run gate
node tools/runtime-check.mjs --strict-site     # 占位域名从警告升成红
```

线上逐项：

1. `/rss.xml`、`/sitemap-index.xml`、`og:url` 三处绝对地址是真域名，不是 `mistwood.example.com`。
2. `/assets/bg-light.jpg` 与 `/assets/bg-dark.jpg` 两张都 200，且**必须成对换**（同构图是主题切换成立的前提，见规范 §5）。
3. 字体那一跳按**规范 §16 那条判据**读回三件见证物（`document.fonts.size` ＋ 本地同名安装 ＋ `transferSize`；`fonts.check()` 与 computed family 名都不算证据）。
4. 双主题 × 四时段截图肉眼过一遍（像素 A/B 必带 `--force-prefers-reduced-motion`，否则那三根无限循环雾带会造出几百 KB 的假差值）。

### 3.5 这一节里哪些是实测、哪些不是

- **实测（本机当场跑的）**：四条端点的可达性（`api.vercel.com` 403、`vercel.com/new` 200、`api.netlify.com` 超时、`fonts.loli.net` 200／`fonts.googleapis.com` 证书被拦）；Astro 版本与 `engines`；`package-lock.json` 存在；`dist/` 是纯静态产物；`runtime-check` 依赖本机 headless Edge（它的实现就起进程）。
- **未验到（按 Vercel 文档假设，第一次真部署要回来打钩）**：① "Vercel 服务器端从 GitHub 拉、不受本机 git 传输层限制"——本机无法证；② Vercel 上 Astro 的 Framework Preset 是否真能自动识别、Output 默认值是否为 `dist`；③ `VERCEL_ENV` 在生产构建里的实际取值（守卫就是靠它判，取值错了守卫会误放或误拦）；④ Node 22 那档镜像里 `npm ci` 的实际耗时与 lockfile 兼容性。这四项**都不影响 3.4 那条本地验收**，但影响"第一次上线到底成不成"。

## 5. 故障签名（症状 → 根因，这一堆都是真踩过才写下来的）

| 症状 | 根因 | 出处 |
|---|---|---|
| 详情页正文整篇塌成一枚 `<p>`、`## 标题` 以字面文本出现，而 build 全绿 | 稿件在盘上是 CRLF，`renderMd` 按 `/\n{2,}/` 切块时 `\r\n\r\n` 中间夹着 `\r`，一块都没切开。**检查归一、渲染不归一**是这一类 bug 的形状 | 规范 §16「正文结构对账」 |
| `git diff` 看不到改动，却确实有改动 | `git checkout <ref> -- path` 连索引一起写 ⇒ 判"现在是哪版文件"要 `git diff HEAD` 或直接 grep 工作树 | 本仓约定 |
| 两档（改前/改后）读数**一模一样**，看着像"改动没生效" | 十有八九是量具坏了：给静态产物起 http 服务时把 before/after 做成 **path 前缀**，而 HTML 里资源是绝对路径 `/_astro/*.css` ⇒ CSS 全 404，页面在零样式下读数。每次导航断言 `document.styleSheets.length` | 2026-09-28 踩 |
| 远程字体"取不到"（`document.fonts.size = 0`）就宣判那批字形读数是回退字 | **不成立**。本机 `HKLM\...\Fonts` 里装着 `NotoSerifSC-VF.ttf`，`"Noto Serif SC"` 这枚名字命中本地同名安装，与镜像窗口是同一张脸（十枚推进宽逐位相同）。在场判定要三件同读 | 规范 §16 判据 |
| `resource timing` 的 `responseStatus = 0` 被读成"请求失败" | 跨源不带 `Timing-Allow-Origin` 时它恒读 0。**0 ≠ 失败**，看 `transferSize` | 同上 |
| 拿两次不同 build 的产物做全图相减，关于页报几万枚像素变化 | 那页 colophon 有三行是**构建派生值**（源码 KB、提交数、构建时刻）。两次 build 天然不同，必须先排除这三行 | 规范 §9 渐隐那格 |
| `border-top` 挪进伪元素后，整根线往下漂 1px | 占位 `border-top:1px solid transparent` 会把 **padding box** 顶下来 1px，而绝对定位的包含块正是 padding box ⇒ 线要写 `top:-1px` | 规范 §9 |
| 详情页正文一填配图，`.frame` 就塌成 2px 高 | `mistwood.css:409-411` 给 `.post-body img` 上 `position:absolute; inset:0`，`essay.css:228` 的 `position:static` 本意是把它拉回原比例，但同权重 `(0,1,1)` 比加载顺序、essay 层排在共享底座**之前** ⇒ 绝对定位那条赢，图铺进一帧没有自身高度的盒子。今天不炸只因为三篇稿子正文配图 0 枚 | 待办（规范 §8.4 末那格记了修法三步） |
| 子代理"finished"但回执是空串 | 去读分支 ref 与工作区，别信通知。两种形状：**零痕迹**（可重派）／**实现体在盘上**（wip 钉住再 rebase，不许重派） | 本仓调度约定 |
