# 视觉优化头脑风暴提案（2026-10-01）

> 性质：发散提案，不是实施计划。每条都标了「守哪条已签规矩」「动哪里」「代价」。
> 前提：整体风格地基不动——同族色、慢动效、三种模糊、磨砂不抛光、五律与 §12 禁区全部照旧。
> 这份文档里**没有任何一条**撞 §12 已否决项（粒子点击、打字机、视频背景、第三主题、第二层噪点、语法高亮、评论区、年度总结页等均不在内）。
> 要开工的条目须回到《设计规范》走一遍签字流程；「⛔」前缀＝会碰已签禁令，需作者点头破例。

---

## 一、定位判读：现在的「现代化缺口」在哪

「晨雾森林」的材质、动效、色彩系统已经完成度极高。与 2026 年第一梯队的个人博客（如 sites.google 化的 editorial blog、Substack/Are.na 系、日本系 minimalist 站点）相比，差距**不在氛围**，在**编排信息的能力**：

1. **列表信息密度偏低**：目录行是大块呼吸排版，读三篇很好，将来三十篇时会成"翻不完的册子"。
2. **视觉锚点少**：全站克制到几乎没有"记号"系统——读者记不住任何一枚图形语言。
3. **"个人博客"的身份感还停在暗处**：作者的痕迹（观察日志、notes、载入次数）都在，但没有一个"这个站是谁的"的正面回答。
4. **现代化的交互细节缺位**：平滑滚动锚点、键盘导航提示、图片点击行为、移动端单手操作等"2026 默认动作"有几处缺。
5. **首屏与正文的语言是两套**：首屏是场景（雾、光、照片），正文是纸。中间缺一段过渡的编排。

以下八组提案按"现代博客该有的样子"逐组回应，每组只动编排与记号层，不动材质与动效纪律。

## 二、方向 A：记号系统——给森林造一枚"路标"

**现象**：全站可复用的视觉记号只有两枚苔绿短线（2px 悬停 / 32px 章），而且都藏在交互与详情页里。读者对整个站"长什么样"没有一个能复述的画面。

### A1 · 晨标（mist mark）：一枚全站统一的小记号
- 一枚极小的图形语言：比如一道斜的雾线 + 一点苔（`--moss` 2px 圆点），作为"这是 Mistwood"的印记。
- 落点：导航左侧站名旁（替代或伴随现有文字 logo）、404 页、打印页脚、favicon 换源。
- 守的规矩：不新增色相；不是图标库，全站只有这一枚；SVG 内联、参与字体子集同一条构建链。
- 代价：需要一次"这一枚到底长什么样"的专门设计（建议从雾带横线的形状出发，不要引入树叶/房屋等具象物——具象符号撞 §0 磨砂意象的风险极高）。
- 收益：读者第一次有了一枚"能记住这个站"的图形；OG 图、分享卡片也有了一枚可用的身份件。

### A2 · 章节记号的"层次化"
- 现状：32px 苔绿短线 = 章；2px = 悬停。两枚是同一族、靠长度区分，很好。
- 提案：给列表页的**年份分节**也立一枚同族记号（比如 `--straw` 枯草金的 1px 点或 6px 短线），把"年份"从纯排版升级成"记号"。
- 代价：枯草金配额是"每屏 ≤2 次"（§12），年份记号出现在列表页顶部会与既有用量冲突——需要先算一遍每屏同时可见枚数。
- 备选：用 `--ink-3` 的加粗圆点（不占枯草金配额，但弱一档）。

## 三、方向 B：列表编排——为"写到第三十篇"做准备

**现象**：目前 3 篇稿，目录行的大留白是奢侈的优雅；但个人博客的真问题是**长期累积后的可扫读性**。

### B1 · 密度自适应的目录行
- 行高与摘要不写死：文章数 ≤6 时保持现状（大留白全文）；>6 时同一份模板自动换到"紧一档"的行距（摘要截到一行、行距从 X 收到 Y）。
- 机制：构建期拿到文章总数，写一个 `data-density="sparse|compact"` 到 `<body>`，CSS 两档。
- 守的规矩：两档都是签过字的"故意"数值；切换是离散的（不是连续缩放）；行仍是整行可点。
- 收益：三篇时的呼吸感一天不减，三十篇时不用重写列表页。这正是"现代化"博客与"做一次就定型"静态页的分水岭。

### B2 · 列表页的"月相"分节
- 现状：年份分节已有。提案：当某年文章数 ≥12 时，年份内再按季度出一道更轻的分节（只一条 `--line` 发丝线 + `--ink-3` 季度名，不加背景）。
- 守的规矩：不新增材质；分节文字是全小写宽字距那一族（§12 禁大写标签的同族延续）。

### B3 · 阅读状态的可视化（已访问之外的第二层）
- 现状：`:visited` 墨色差已落地（`--ink-visited`）。
- 提案：列表行的**编号/日期列**可以用等宽数字 + `tabular-nums` 已签的那一族做"竖排对齐"——让日期在视觉上排成一条直尺，扫读时眼睛有参照。
- 这是纯排版改进，零新机制。

## 四、方向 C：阅读体验——2026 年博客的"默认动作"补齐

### C1 · 锚点标题的可见性
- 现状：`<h2>` 是裸标签，无编号、无锚点链接。
- 提案：悬停（桌面）/点按（触屏）标题时，标题左侧浮现一枚 `--moss` 的 `#` 链（可点击复制锚点）。这是 2026 年 editorial 站点的标准件。
- 守的规矩：锚点必须真实存在（§12 死锚点禁令）；无 JS 时锚点本身是 `id`，只是没有那个 `#` 记号——降级正确。
- 与 §12 "当前章不许加左竖线"不冲突：那是目录的"当前"记号，这是标题的"链接"记号，语义不同；但落笔前要核对 §9 "同一符号两种意思"那一族。

### C2 · 键盘导航提示
- 现状：`:focus-visible` 有苔绿描边，但"按 Tab 能走到哪"对读者不可见。
- 提案：首次按 Tab 时，在视口下缘浮出一条 `--glass` 材质的提示条（"Tab 移动 · Enter 打开 · / 搜索"），三秒后淡出；只显示给键盘用户（`keydown` 触发过才记）。
- 守的规矩：一次性、可核对的差别（不是随机短句池）；3s 淡出是交互反馈档边缘，需核 §1.3。
- 这是"现代化"最实打实的一条——无障碍提示在 2026 年的个人站已是头部实践。

### C3 · 图片的"放大"行为
- 现状：内容照片入场虚焦散开（§8.4），之后不可交互。
- 提案：点击内容照片 → 进入"灯下看"模式：照片铺满视口、背景压一层更深的 `--scrim`、Esc/点击退出。
- 守的规矩：不是 lightbox 插件那一套（撞"涟漪"族的弹窗动画风险高）；进出场用已签的 0.6s 虚焦散开逆过程；这是"同一处动"预算内的一次性动作。
- 代价：需要一次"纱罩层级"的复核（§5 照片三笔账的第四笔）。
- ⏸ 这条影响面最大，建议排在最后。

### C4 · 阅读进度，但不是进度条
- 进度条撞"平台语言"族（§12 年度报告同族）。本站式答案：**已有的章节滚动高亮（目录"当前章"）就是进度**，强化它即可——比如目录在窄屏收成顶部一条时，当前章名字保持可见。
- 零新机制，只是让既有记号的降级形态更完整。

## 五、方向 D：首屏——场景与纸之间补一段"过渡编排"

**现象**：首屏是完整的场景（雾、光、照片、Hero），往下一滚立刻变成纯白纸张式的目录。中间少一拍。

### D1 · Hero 之下的"一句引子"
- 在 Hero 与目录之间插入一段窄栏（最大宽 ~32em，居中），放一句**作者真实写过的话**（从 notes 或 about 里挑，常显，不轮换——§12 禁随机短句池）。
- 排版：斜体、`--ink-2`、行间两侧各一枚 `--line` 短划。
- 守的规矩：常显 + 真实出处 = §7 人格层的正例；不是"浮出 2 秒消失"的被否形态。
- 收益：首屏的"场景语言"有一个降调出口，滚到目录时不觉得换了一个站。
- **判定（2026-10-02 `v10b/home`）：判不进为新增载体。** 干净检出上"一句作者真实写过的话"没有合法载体（`src/content/notes/` 出厂零枚、`.gitignore:29` 挡着，三篇样例稿全 `draft: true` ⇒ 不可见的句子没有出处），而唯一合法载体（最新一条手记）已经被首页下半段那枚 `.home-note` 占着——再在 Hero 与目录之间落一块，就是同一枚值在同一页上屏两次、并多出第二枚去 `/notes/` 的锚点。判不进的两态都当众量过（出厂态那块在产物里 **0 字节**：`</main>` 与 `<section class="home-lower">` 直接相邻；有载体态句子与出处逐字来自那条临时手记，量完删掉、不进仓库），落法与牙登记在规范 §5 那一格末尾 ＋ `tools/taxonomy-check.mjs` 第 ⑦ 格。上面那套排版（`~32em`、居中、斜体、`--line` 短划）没有落点，因为它挂的那一块不落 ⇒ `src/styles/*.css` 里 `32em` 至今 0 处。

### D2 · 首屏时钟的可读性升级
- §6 的时间感知系统是全站独一份的资产，但目前它主要在"感受"层。
- 提案：导航或 Hero 角落加一枚**极简**的时刻文字（"清晨 · 雾未散"这类来自真实时段的词），由同一枚时钟驱动。
- 守的规矩：文字必须对应真实时段计算结果（§12 假数字族）；词表是封闭的、签过字的；分钟级更新不触发任何动画（文本替换）。
- ⛔ 注意：§12 登记过"给年度弧补读数"的否决——那条禁的是"拿得到的数字被装饰化"。本条的文字是**时段的定性描述**不是数字读数，但落笔前必须把这两条摆在一起让作者判一次，确认不是同族。
- **判定（2026-10-02 `v10b/home`）：极简时刻文字已被 `.hero-watch` 承担，多出的那半句判不进。** 承担的那一半＝同一根时钟（`src/scripts/site.js:305-333` 的 `tick()`）算出的 `phase` 填一枚封闭词表里的中文时段字（`site.js:819`），四档上屏文本实测 dawn=`初`／day=**空**／dusk=`暮`／night=`守夜`（1440×900 与 390×844 两档视口、减弱偏好档、无 JS 档都量过，读数与量具行程那一双见规范 §6 那一格）。剩下的缺口正是样例『清晨 · 雾未散』里"雾未散"那一半——它**没有真值可对应**：站内算得出的只有时刻（四档 `phaseAt` ＋ 两枚 `shaftAt` 子区间），没有雾况（`#weather-word` 那四个词是时段的拉丁别名、`.mist-band` 那三条是常驻动画），落它只能造句；与 :2122 那条「给年度弧补读数」按提案的要求摆在一起判过一次——那条禁"拿得到的数字被装饰化"、本条是"拿不到的量被文字化"，**不同族**，否决它的不是 :2122 而是 §12 那句"句子必须对应真实内容"＋:1474 那句「再长就要造句」。"常显"那一半同样落不了：静态产物上烘死一个值＝四分之三时间在说谎，交给脚本＝回到 :1476 点名过的形状。**判不进的落法有牙**：`tools/phase-check.mjs` 第 ⑧ 格钉词表封闭（枚数／键／逐字值／规范签字行同源／模板不带字），`npm run selftest` 17/17 反例、9/9 朝窄。

## 六、方向 E：排印深化——把已铺好的字体底座用起来

§3.3 的 wght 可变轴已自托管落地（300/400/550/700 四档读得出差别），但 550 这一档目前**没有设计语言去挂**。这是现成的、零加载代价的现代化弹药。

### E1 · 550 的落点提案（三选一）
1. **卡片/目录行标题悬停**：400 → 550（不是 700），比换色更内敛的一档强调；
2. **正文中的强调短语**：`<strong>` 从 700 降到 550——700 在 CJK 里偏"喊"，550 更像"加重了语气说"；
3. **导航当前页**：替代或伴随现有下划线记号。
- 每条都要先过 §2.4 对比度复算（550 笔画变细不影响字色，但字重视觉重量变化要复核）。
- 守的规矩：这是把已签的载体接上设计语言，不是新增字体请求。

### E2 · 中西文混排的"引文块"升级
- 引用块（blockquote）现状：左侧 1px 竖线 + `--ink-2`。
- 提案：引文内的西文段落改用衬线斜体（拉丁族已自托管 italic？需核查），中文保持正体——这是 2026 年双语 editorial 的标准做法，比整段斜体克制。
- 守的规矩：零新字体文件（用已有族的字样式）。

### E3 · 标点的悬挂
- `hanging-punctuation` 在正文段落开启（Safari/Chrome 均已支持），让行首引号、行尾句号挂出版心——中式排版的"避头尾"现代等价物。
- 零资源代价，纯 CSS 一行，但需要逐页复核对齐读数（特别是目录行的右缘）。

## 七、方向 F：暗色「夜林」——再往下走半步

**现象**：夜林是"重新打光"不是反色，这个立意已经很高。但 2026 年的头部站点在暗色上普遍多做一件事：**暗色下的材质层次比亮色更丰富**（因为暗底上透明度差更好读）。

### F1 · 夜林的玻璃分层
- 亮色下 `--glass` 面是同一张磨砂；夜林下可以让导航玻璃与卡片玻璃有**半档**明度差（比如导航再亮 2%）——夜里"离地更高"的玻璃读得出海拔。
- 守的规矩：同族色内明度差（§1.1 正例）；`palette-check` 的十四档复算自动覆盖。

### F2 · 萤火虫在夜林里的"主场"
- 萤火虫（§8.6）在亮色下是彩蛋，在夜林下是"本来就属于这里"。
- 提案：夜林下首屏的常驻循环名额分配向萤火虫倾斜一档（比如雾带 3 条 → 雾带 2 条 + 萤火虫）——名额不变（§1 预算 ≤3），只是配比随时段换。
- 守的规矩：预算是上限不是义务，配比换档是已签框架内的动作；但"§1 那张表写的是雾带×3 或雾带+萤火虫"，本提案落在"或"字的右半边，需要规范补一句"夜林配比"。

## 八、方向 G：小屏与打印——两个常被忘掉的"现代化"战场

### G1 · 移动端单手区
- 导航的主要触点（搜索、主题、菜单）收进屏幕下半拇指弧内（`env(safe-area-inset-bottom)` + 底部玻璃条形态）。
- 现状若已是顶部条，这是一次真改版；需要先核对 §11 降级表现状再定稿。

### G2 · 打印的第二张名片
- §19 打印版式已经极完整。补一枚小的：打印页脚的"晨标"（A1 若立）+ 站点地址文字——让打印出来的纸也能被认出出处。
- 零风险。

## 九、方向 H：关于页——把"这是谁的站"答在明处

### H1 · 名片区
- 关于页顶部的头像 + 一段手写感的签名行（作者手写签名扫描件？——若提供素材）。
- 若不用真签名：用已自托管的衬线 italic 写一句签名式的话，配晨标。
- 守的规矩：AI 生成插图是禁区（§12）——签名必须是真素材或纯排印。

### H2 · "这个站是怎么做的"一节
- 2026 年个人博客的通行件：colophon 扩充成一小节——字体（自托管 Noto Serif/Sans SC）、框架（Astro）、托管（Cloudflare Pages）、以及"没有统计脚本"这句宣言。
- 这句宣言本身就是人格（§7），而且它是**真数字的反面声明**：明确告诉读者"这里没有追踪你"。

## 十、优先级建议（如果只做三件）

| 序 | 条目 | 理由 |
|---|---|---|
| 1 | **B1 密度自适应 + B3 日期对齐** | 纯编排、零风险、立刻让列表"像 2026 年的博客"；且为将来写稿铺路 |
| 2 | **D1 首屏引子 + E1 字重落点（选 2：strong 550）** | 补"场景到纸"的断层；把已付费的可变轴弹药用起来，阅读质感是读者每天摸到的东西 |
| 3 | **A1 晨标** | 全站唯一缺的"身份件"；一旦立住，OG、favicon、打印、名片全部受益 |

排在后面的：C3 图片灯下看（改动面最大）、F2 夜林配比（要改 §1 表）、D2 时刻文字（要过一次 ⛔ 裁决）。

## 十一、本提案明确不做的（与 §12 对账后的自查）

- 不动色彩家族、不加第五色、不加外来色相；
- 不加第四种模糊、第四种缓动；
- 不加任何常驻循环（所有动效提案都在既有名额内换配比）；
- 不加第二层噪点/纹理、不动颗粒；
- 不做语法高亮、评论区、年度总结、访问量、随机短句池；
- 不做第三主题、视频背景、AI 插图；
